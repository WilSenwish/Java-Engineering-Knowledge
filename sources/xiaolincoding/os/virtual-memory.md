本篇跟大家说说**内存管理**，理解了它，至少对整个操作系统的工作会有一个初步的轮廓，这也难怪面试的时候常问内存管理。

## 虚拟内存

如果你是电子相关专业的，肯定在大学里捣鼓过单片机。单片机是没有操作系统的，所以每次写完代码，都需要借助工具把程序烧录进去。另外，**单片机的 CPU 是直接操作内存的「物理地址」**。在这种情况下，要想在内存中同时运行两个程序是不可能的，这两个程序会立刻崩溃。

操作系统如何解决？关键是这两个程序都引用了绝对物理地址。可以把进程所使用的地址「隔离」开来，即让操作系统为每个进程分配独立的一套「**虚拟地址**」，每个进程都不能访问物理地址，虚拟地址最终怎么落到物理内存里对进程透明。

**操作系统会提供一种机制，将不同进程的虚拟地址和不同内存的物理地址映射起来。** 程序访问虚拟地址时，由操作系统转换成物理地址再访问内存。

于是引出两种地址：

- 程序所使用的内存地址叫做**虚拟内存地址**（Virtual Memory Address）
- 实际存在硬件里面的空间地址叫**物理内存地址**（Physical Memory Address）

操作系统引入虚拟内存，进程持有的虚拟地址会通过 CPU 芯片中的内存管理单元（MMU）的映射关系转换成物理地址。

操作系统管理虚拟地址与物理地址之间的关系主要有两种方式：**内存分段和内存分页**。

## 内存分段

程序是由若干个逻辑分段组成的，如代码分段、数据分段、栈段、堆段组成。**不同的段有不同属性，所以用分段（Segmentation）的形式把这些段分离出来。**

**分段映射**：虚拟地址由**段选择子**和**段内偏移量**组成。

- 段选择子保存在段寄存器里，最重要的是**段号**，用作段表索引；
- 段表保存段的基地址、段的界限和特权等级等；
- 段内偏移量应在 0 和段界限之间，合法则将段基地址 + 段内偏移量得到物理地址。

例：访问段 3 偏移量 500 的虚拟地址 → 段 3 基地址 7000 + 500 = 7500。

**分段的两个不足**：

1. **内存碎片**：不会产生内部碎片（按需分配），但段长度不固定会产生**外部碎片**（多个不连续小物理内存导致新程序无法装载）。解法是**内存交换**（Swap）：把音乐程序占用的 256MB 写到硬盘，再紧跟在已占用的 512MB 后面读回来，空缺出连续空间；
2. **内存交换效率低**：每次交换要把一大段连续内存写到硬盘，交换大程序时整个机器卡顿。

## 内存分页

**分页是把整个虚拟和物理内存空间切成一段段固定尺寸的大小**，这样一个连续且尺寸固定的内存空间叫**页**（Page）。Linux 下每页大小为 `4KB`。

**分页映射**：虚拟地址分为**页号**和**页内偏移**。页号作为页表索引，页表包含物理页所在物理内存的基地址，基地址 + 页内偏移 = 物理地址。三步转换：① 切分虚拟地址为页号和偏移量；② 按页号查页表得物理页号；③ 物理页号 + 偏移量得物理地址。

**解决分段问题**：页与页紧密排列，**无外部碎片**；但最小单位是一页，**有内部碎片**（不足一页也分一页）。内存交换时一次只写少数页，**效率高**。且支持**按需加载**（只在用到对应虚拟内存页时才加载）。

**缺页异常**：进程访问的虚拟地址在页表中查不到时，系统产生缺页异常，进入内核空间分配物理内存、更新页表，再返回用户空间恢复运行。

### 简单分页的缺陷与多级页表

32 位环境虚拟地址空间 4GB，页大小 4KB（2^12），需要约 100 万（2^20）个页表项，每项 4 字节，单进程页表就要 **4MB**；100 个进程就要 400MB。

**多级页表**：把一级页表再分页——一级页表 1024 项，每项指向一个含 1024 个页表项的二级页表。利用**局部性原理**，某个一级页表项没用到就不创建对应二级页表。假设 20% 一级页表项被用到，占用 4KB + 20% × 4MB = 0.804MB，对比 4MB 是巨大节约。

64 位系统用四级目录：PGD → PUD → PMD → PTE。

### TLB

多级页表解决空间问题，但地址转换多了几道工序，带来时间开销。利用局部性原理，在 CPU 芯片中加入存放最常访问页表项的 Cache——**TLB**（Translation Lookside Buffer，页表缓存/快表）。CPU 寻址先查 TLB，未命中才查常规页表。

## 段页式内存管理

分段和分页可组合使用：先分段，再把每段划分为多个页。地址结构由**段号、段内页号和页内位移**三部分组成。得到物理地址须三次内存访问：段表 → 页表 → 物理页号 + 位移。

## Linux 内存布局

Intel 从 80286 开始用段式管理，80386 起页式管理建立在段式之上——段式映射出的地址称「线性地址」（虚拟地址），再由页式映射到物理地址。

**Linux 主要采用页式管理，但不可避免地涉及段机制**：Linux 让每个段都从 0 地址开始覆盖整个 4GB 虚拟空间，所有段基地址一样，相当于屏蔽逻辑地址概念，**段只被用于访问控制和内存保护**。

**虚拟地址空间分内核空间和用户空间**：

- 32 位：内核空间 1G 位于最高处，其余 3G 用户空间；
- 64 位：内核空间和用户空间各 128T，分别占最高和最低处。

进程在用户态只能访问用户空间，进入内核态才能访问内核空间。每个进程虚拟内存中的内核地址关联相同的物理内存，方便切换到内核态后访问。

**用户空间从低到高 6 段**：代码段（二进制可执行代码）、数据段（已初始化全局/静态常量）、BSS 段（未初始化静态/全局变量）、堆段（动态分配，向上增长）、文件映射段（动态库/共享内存，向上增长）、栈段（局部变量/函数上下文，固定 8MB 可调）。代码段下方有保留区（防止 NULL 等小地址访问跑飞）。

## 总结

1. 操作系统为每个进程分配独立虚拟地址空间，进程间内存隔离；
2. 物理内存紧张时通过**内存交换**（Swap）把不常用内存换出到硬盘；
3. 虚拟地址到物理地址的映射有**分段**和**分页**两种方式，可结合（段页式）；
4. 分段按逻辑分（代码/数据/栈/堆），连续空间但有外部碎片和交换效率问题；
5. 分页固定 4KB，无外部碎片、交换高效，但有内部碎片和页表过大问题；
6. **多级页表**解决页表空间问题，**TLB** 解决转换速度问题；
7. Linux 主要分页、段仅用于访问控制和内存保护。

**虚拟内存的作用**：① 运行内存可超过物理内存（局部性 + Swap）；② 每进程页表私有，解决多进程地址冲突；③ 页表项有权限标记位，提供内存访问安全性。
