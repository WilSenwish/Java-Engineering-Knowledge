TCP **巨复杂**，它为了保证可靠性，用了巨多的机制来保证，真是个「伟大」的协议。

TCP 是通过序列号、确认应答、重发控制、连接管理以及窗口控制等机制实现可靠性传输。本文重点介绍 **重传机制、滑动窗口、流量控制、拥塞控制。**

## 重传机制

常见的重传机制有：超时重传、快速重传、SACK、D-SACK。

### 超时重传

在发送数据时，设定一个定时器，当超过指定的时间后，没有收到对方的 `ACK` 确认应答报文，就会重发该数据。

TCP 会在以下两种情况发生超时重传：数据包丢失、确认应答丢失。

**RTO 的计算**：超时重传时间是以 `RTO`（Retransmission Timeout）表示。

- RTO 较大时，重发慢，性能差；
- RTO 较小时，可能没丢就重发，增加网络拥塞，导致更多超时、更多重发。

**RTO 应该略大于报文往返 RTT**。但 RTT 是经常波动的，所以 RTO 必须是动态值。

RFC6289 建议公式：`RTO = SRTT + 4 * DevRTR`（Linux 参数 α=0.125、β=0.25、μ=1、∂=4）。

**超时间隔加倍**：每次超时重传，都将下一次超时时间间隔设为先前值的两倍。

### 快速重传

**不以时间为驱动，而是以数据驱动重传**：发送方收到三个相同的 ACK 报文时，会在定时器过期之前，重传丢失的报文段。

例：Seq2 丢失，Seq3/4/5 到达后接收方都回复 ACK2，发送端收到三个 ACK=2，即重传 Seq2。

### SACK 方法

`SACK`（Selective Acknowledgment，选择性确认）：TCP 头部「选项」字段里携带已收到的数据信息，发送方据此**只重传丢失的数据**。

Linux 参数 `net.ipv4.tcp_sack`（2.4 后默认打开）。

### Duplicate SACK

`D-SACK`：用 SACK 告诉发送方**有哪些数据被重复接收了**。

- **ACK 丢包场景**：接收方回 `SACK = 3000~3500`（此时 ACK 已到 4000），告知发送方数据没丢，是 ACK 丢了；
- **网络延迟场景**：数据包被延迟，触发快速重传后延迟包又到达，接收方回 `SACK=1000~1500`，告知是网络延迟不是丢包。

**D-SACK 的三个好处**：① 区分是数据包丢了还是 ACK 丢了；② 知道是否被网络延迟；③ 知道网络是否复制了包。

Linux 参数 `net.ipv4.tcp_dsack`（默认打开）。

## 滑动窗口

**引入原因**：每发一个数据都要等确认应答，RTT 越长效率越低。窗口 = 无需等待确认应答可继续发送数据的最大值。

**累积确认**：ACK 600 丢失没关系，收到 ACK 700 就意味着 700 之前的数据都收到了。

**窗口由谁决定**：TCP 头 `Window` 字段是**接收端**告诉发送端自己还有多少缓冲区，发送方按接收方能力发送。

**发送方窗口四分区**（三指针管理）：

- #1 已发送并收到 ACK（SND.UNA 之前）
- #2 已发送未收到 ACK（SND.UNA ~ SND.NXT）
- #3 未发送但接收方可处理（SND.NXT ~ SND.UNA+SND.WND）
- #4 未发送且超接收方范围

可用窗口 = `SND.WND - (SND.NXT - SND.UNA)`

**接收方窗口**：`RCV.WND`（通告给发送方）+ `RCV.NXT`（期望的下一个字节）。

**收发窗口约等于相等**：新窗口通过报文 Window 字段通告，存在时延。

## 流量控制

发送方根据接收方的实际接收能力控制发送量，避免填满接收方缓存触发重发。

**窗口收缩实例**：服务端繁忙、应用层不读取 → 缓冲区占用 → 接收窗口从 360 收缩到 260 → 80 → 0。

**关键规则**：TCP **不允许同时减少缓存又收缩窗口**（否则丢包），而是先收缩窗口，过段时间再减少缓存。

**窗口关闭与死锁**：窗口为 0 时，通告窗口的 ACK 若丢失，双方死等。解法：**持续定时器**，超时发**窗口探测报文**（Window probe），一般 3 次、每次 30-60 秒，仍为 0 则发 RST 断连。

**糊涂窗口综合症**：接收方腾出几个字节就通告、发送方就发几个字节——TCP+IP 头 40 字节为几个字节数据打工。

- 接收方策略：窗口 < min(MSS, 缓存/2) 时通告 0，等窗口 ≥ MSS 或缓存一半可用再打开；
- 发送方策略：**Nagle 算法**（默认开启），条件二满足才发：① 窗口 ≥ MSS 且数据 ≥ MSS；② 收到之前数据的 ACK；
- 交互式程序（telnet/ssh）需 `TCP_NODELAY` 关闭 Nagle。

## 拥塞控制

**与流量控制的区别**：流量控制怕填满**接收方**缓存；拥塞控制怕填满**整个网络**。

`swnd = min(cwnd, rwnd)`。发生超时重传即认为网络拥塞。

**四个算法**：

| 算法 | 触发/条件 | 规则 |
|------|-----------|------|
| 慢启动 | 连接建立后 cwnd < ssthresh | 每收到一个 ACK，cwnd +1（**指数增长**） |
| 拥塞避免 | cwnd ≥ ssthresh | 每收到一个 ACK，cwnd + 1/cwnd（**线性增长**） |
| 拥塞发生 | 超时重传 | ssthresh = cwnd/2，cwnd = 1，重新慢启动（一夜回到解放前）|
| 快速恢复 | 快速重传（3 个重复 ACK） | cwnd = cwnd/2，ssthresh = cwnd，cwnd = ssthresh + 3；每收到重复 ACK cwnd+1；收到新数据 ACK 后 cwnd = ssthresh，回到拥塞避免 |

Linux 每连接 cwnd 初始值为 10，可用 `ss -nli` 查看。
