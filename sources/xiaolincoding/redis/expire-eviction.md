Redis 的「内存淘汰策略」和「过期删除策略」，很多小伙伴容易混淆，这两个机制虽然都是做删除的操作，但是触发的条件和使用的策略都是不同的。

## 过期删除策略

Redis 可以对 key 设置过期时间，需要有机制将已过期的键值对删除。

### 如何设置过期时间？

4 个命令：

- `expire <key> <n>`：n 秒后过期
- `pexpire <key> <n>`：n 毫秒后过期
- `expireat <key> <n>`：某个时间戳（秒）后过期
- `pexpireat <key> <n>`：某个时间戳（毫秒）后过期

设置字符串时同时设置过期时间的 3 种命令：`set <key> <value> ex <n>`、`set <key> <value> px <n>`、`setex <key> <n> <valule>`。

查看剩余存活时间：`TTL <key>`；取消过期时间：`PERSIST <key>`（之后 TTL 返回 -1 表示永不过期）。

### 如何判定 key 已过期？

每设置一个 key 过期时间，Redis 会把该 key 带上过期时间存储到一个**过期字典**（expires dict）中：

```c
typedef struct redisDb {
    dict *dict;    /* 数据库键空间，存放着所有的键值对 */
    dict *expires; /* 键的过期时间 */
    ....
} redisDb;
```

- 过期字典的 key 是指向某个键对象的指针；
- 过期字典的 value 是 long long 类型的整数，保存过期时间。

查询 key 时，Redis 首先检查是否在过期字典中：不在则正常读取；在则获取过期时间与当前系统时间比对，比系统时间大则未过期，否则判定已过期。

### 三种过期删除策略

**定时删除**：设置过期时间时同时创建定时事件，时间到达由事件处理器自动删除。

- 优点：过期 key 会被尽快删除，内存尽快释放，**对内存最友好**；
- 缺点：过期 key 多时删除占用大量 CPU 时间，**对 CPU 不友好**。

**惰性删除**：不主动删除，每次访问 key 时检测是否过期，过期则删除。

- 优点：只用很少系统资源，**对 CPU 最友好**；
- 缺点：过期 key 没被访问就一直占内存，**对内存不友好**。

**定期删除**：每隔一段时间随机取出一定数量的 key 检查并删除过期 key。

- 优点：限制删除操作的时长和频率，减少对 CPU 影响，同时删除部分过期数据；
- 缺点：难以确定执行时长和频率——太频繁变定时删除，太少变惰性删除。

### Redis 的选择：惰性删除 + 定期删除

**惰性删除实现**（db.c `expireIfNeeded`）：访问或修改 key 前调用检查，过期则删除；异步还是同步删除由 `lazyfree_lazy_expire` 参数决定（Redis 4.0+）。

**定期删除实现**（expire.c `activeExpireCycle`）：

- 默认每秒 10 次（`hz 10` 可配置）；
- 每轮随机抽查 **20 个** key（`ACTIVE_EXPIRE_CYCLE_LOOKUPS_PER_LOOP` 写死）；
- 若本轮已过期 key 数量 > 5 个（占比 > 25%），继续重复抽查；否则等下一轮；
- 循环时间上限默认 **25ms**，防止线程卡死。

## 内存淘汰策略

当 Redis 运行内存超过 `maxmemory` 设置的最大内存，触发内存淘汰策略删除符合条件的 key。

**maxmemory 默认值**：64 位系统默认 0（无限制，直到崩溃）；32 位默认 3G。

### 八种内存淘汰策略

**不淘汰**：

- `noeviction`（Redis 3.0 后默认）：不淘汰任何数据，新写入报错，但查询/删除仍可用。

**在设置了过期时间的数据中淘汰**：

- `volatile-random`：随机淘汰设置了过期时间的任意键值；
- `volatile-ttl`：优先淘汰更早过期的键值；
- `volatile-lru`（3.0 前默认）：淘汰设置了过期时间的键值中最久未使用的；
- `volatile-lfu`（4.0+ 新增）：淘汰设置了过期时间的键值中最少使用的。

**在所有数据范围内淘汰**：

- `allkeys-random`：随机淘汰任意键值；
- `allkeys-lru`：淘汰整个键值中最久未使用的；
- `allkeys-lfu`（4.0+ 新增）：淘汰整个键值中最少使用的。

查看：`config get maxmemory-policy`；修改：`config set maxmemory-policy <策略>`（立即生效，重启失效）或改配置文件（重启生效）。

## LRU 算法和 LFU 算法有什么区别？

### 传统 LRU 的问题

传统 LRU 基于链表，最新操作的键移到表头，淘汰时删链表尾部。两个问题：① 链表管理所有缓存数据有额外空间开销；② 数据被访问时移动链表项耗时，降低性能。

### Redis 的近似 LRU

在 Redis 对象结构体中添加额外字段记录**最后一次访问时间**。淘汰时**随机采样 5 个值**（可配置），淘汰最久未使用的那个。

优点：不用维护大链表（省空间）、不用每次访问移动链表（高性能）。

问题：**无法解决缓存污染**——一次读取的大量数据（只读一次）会长期滞留缓存。

### Redis 的 LFU

LFU（Least Frequently Used）根据**访问频次**淘汰，4.0 引入。Redis 对象头 24 bits lru 字段分两段：高 16 bit 存 `ldt`（Last Decrement Time，访问时间戳），低 8 bit 存 `logc`（Logistic Counter，访问频次，新 key 初始值 5）。

**logc 会随时间衰减**：每次访问先按上次访问距当前时长衰减，再按概率增加（logc 越大越难增加）。

两个调优参数：

- `lfu-decay-time`（分钟，默认 1）：调整衰减速度，值越大衰减越慢；
- `lfu-log-factor`：调整增长速度，值越大增长越慢。

## 总结

**过期删除策略** = 惰性删除 + 定期删除，删除对象是**已过期**的 key。
**内存淘汰策略**解决内存过大问题，运行内存超过 maxmemory 时触发，4.0 后共 8 种。
