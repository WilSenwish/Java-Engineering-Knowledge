## 项目定位

面向 **Agentic RAG 演进的生产级 Java AI 应用平台**，覆盖从文档入库到智能问答的完整链路。GitHub 开源：https://github.com/nageoffer/ragent（社群 12306 项目同源团队，1.5w+ Star）。

**核心能力（V2）**：
- **混合检索**：向量、关键词、知识图谱、联网搜索并行召回，支持去重、RRF 融合与 Rerank；
- **问题理解**：查询词映射、问题重写与拆分、树形意图识别、多知识库路由；
- **模型与工具**：模型档位、首包探测、熔断降级，AgentScope MCP 工具发现与调用；
- **会话记忆**：最近 N 轮消息 + 持久化摘要，控制 Token 成本；
- **流量保护**：Redis 公平排队与分布式并发控制；
- **知识闭环**：可编排入库 Pipeline、远程刷新、回答溯源、用户反馈、Trace 与管理后台。

## 七个 Maven 模块（模块化单体）

| 模块 | 职责 |
|------|------|
| `infra-ai` | Chat/Embedding/Rerank/VLM 模型客户端、模型档位、路由、首包探测、健康状态与降级 |
| `system` | 用户认证与审计日志（系统支撑域） |
| `rag` | RAG 问答、知识库、入库 Pipeline、意图树、检索、会话及管理端 API |
| `agent` | AgentScope ReAct 执行引擎，接入知识检索与 MCP 工具，支持技能、记忆和人工确认 |
| `bootstrap` | 启动装配层（启动类 + 主配置） |
| `framework` | 统一响应与异常、幂等、分布式 ID、MQ 适配、SSE 与跨节点流式取消 |
| `mcp-server` | 基于 MCP Java SDK 的独立工具示例服务（天气、票务、销售、联网搜索） |

分层目的：**业务编排、AI 供应商差异、通用基础设施隔离**——切换模型/向量库/对象存储时，核心问答流程不重写。

## v1 vs v2 架构演进

| 维度 | v1（Workflow） | v2（Agentic） |
|------|----------------|---------------|
| 路径决策 | 代码写死：问题重写 → 意图识别 → 多路召回 → 组装生成 | ReAct 循环，路径由模型自定：查不查、查几次、接着干什么 |
| 工具接入 | 不连接 MCP 服务，只识别知识库和系统意图 | AgentScope 发现 MCP 工具；意图树 MCP 节点指定工具与确认规则 |
| 适用场景 | 问答类知识助手（更快更可控） | 需规划、要动手操作的场景（链路长、非线性） |

**两套并存**，不是谁替代谁。

## 设计模式实战（每个模式对应具体问题）

策略（检索通道/结果后处理）、工厂（意图树/分块策略/流式回调）、模板方法（并行检索/模型请求）、注册表（意图节点管理）、装饰器（向量写入同步关键词和图谱索引）、责任链（检索后处理/模型故障降级）、中间件（Agent 记忆注入/上下文压缩/技能遮蔽/工具批处理）、适配器（多家模型方言/Agent MCP 业务规则/MQ 客户端）、状态机（远程文档定时刷新）、事件回调（模型流式响应/首包探测/SSE）、AOP（链路追踪/幂等/审计日志）。

## 生产级特性

| 特性 | 实现 |
|------|------|
| 流量保护 | Redis ZSET 公平排队 + Lua 原子抢占 + 过期信号量 + Pub/Sub 唤醒 |
| 模型容错 | 多候选模型自动切换；首包超时/空响应/异常触发降级；三态熔断隔离故障节点 |
| 检索稳定性 | 多通道并行检索，单通道失败不影响主链；按召回/Rerank/TopK 分层控制规模 |
| 数据一致性 | RocketMQ 事务消息保障分块可靠执行；幂等；远程刷新用分布式锁+状态机 |
| 可观测 | Trace Run/Node 耗时、输入输出、异常；Langfuse 追踪推理/工具调用/Token |
| 流式体验 | SSE 分事件输出思考/正文/来源/推荐问题；全局超时 + 客户端断开取消 |
| Agent 执行保障 | 上下文按水位裁剪与压缩；长期记忆跨会话沉淀；写操作人工确认；执行中断 |
| 安全 | Sa-Token 认证、数据归属校验、上传限流、参数校验、统一异常处理 |

## 工程质量要点

- 10 个专用线程池隔离负载，TTL 保证用户与 Trace 上下文跨线程传递；
- 模型档位、候选能力和检索漏斗在**启动阶段完成一致性校验**，错误配置直接失败（fail-fast）而非静默降质；
- 测试覆盖：模型路由、检索预算、会话摘要、入库 Pipeline、MCP、Agent 上下文与长期记忆；
- 推荐配合社群 oneThread 动态线程池框架搭配学习。

## RAG/Agent 常见误区（面试可聊）

1. 调个 API 就算会 RAG/Agent——真正难点在切分策略、召回率、多路融合、幻觉控制、工具失败处理；
2. RAG 只是检索+生成——涉及文档解析、分块、问题重写、意图识别、检索策略、会话记忆、任务执行全链路；
3. 接入框架和 MCP 就是企业级——增量更新、多租户隔离、成本控制、风控、负载均衡、写操作确认、可观测才是工程分水岭；
4. 只关注模型忽略工程——同模型不同检索/Prompt/分块效果天差地别。
