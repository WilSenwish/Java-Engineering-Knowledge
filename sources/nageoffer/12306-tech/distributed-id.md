## 1. 为什么需要分布式 ID

分布式系统中有些场景需要使用全局唯一 ID。可以使用 36 位 UUID 防止冲突，但 UUID 缺点明显：**相对较长**、**一般无序**。有时希望 ID 简单些且**按时间有序生成**。

## 2. 雪花算法（Snowflake）

Twitter 开源的分布式 ID 生成算法，生成 64bit long 型数值，引入时间戳，基本保持自增。

**优点**：
1. 高性能高可用：生成不依赖数据库，完全内存中生成；
2. 高吞吐：每秒生成数百万自增 ID；
3. ID 自增：存入数据库索引效率高。

**缺点**：依赖系统时间一致性，**时间被回调或改变可能造成 ID 冲突或重复**。

### 2.1 组成结构

| 部分 | 位数 | 说明 |
|------|------|------|
| 不使用（符号位） | 1bit | 固定为 0 |
| 时间戳 | 41bit | 毫秒级，可用 69 年 |
| 标识位 | 5bit 数据中心 ID + 5bit 工作机器 ID | 组合最多支持 1024 个节点 |
| 序列号 | 12bit | 毫秒内递增，每毫秒 4096 个 ID |

**容量计算**：12bit 序列号 → 1 毫秒 4096 个 ID → 1 秒 409.6w ID。

**定制化**：想运行更久增加时间戳位数；支持更多节点增加标识位长度；并发很高增加序列号位数。"雪花算法并不是一成不变的，可以根据系统内具体场景进行定制。"

### 2.2 适用场景

因为有序自增保障 MySQL B+ Tree 索引插入高性能，日常业务中更多应用在**数据库主键 ID 和业务关联主键**。

## 3. ID 重复问题与标识位分配

### 3.1 重复的必要条件

假设订单微服务集群部署三个节点、标识位一致，200 并发均匀散布，三个节点同一毫秒同一序列号生成 ID 即重复。必要条件：
1. 集群部署且部分机器标识位一致；
2. 业务有一定并发量；
3. 同一毫秒下序列号一致。

**结论：如果能保证标识位不重复，雪花 ID 也不会重复。**

### 3.2 开源框架的标识位方案（MyBatis-Plus Sequence）

- `getDataCenterId(maxDatacenterId)`：网络接口为空默认 1L；否则**通过 Mac 地址**计算（取 mac 末两位运算后取模）；
- `getWorkerId(datacenterId, maxWorkerId)`：**MAC + PID 的 hashCode** 取 16 低位运算；
- Hutool v5.7.9 参照了 MyBatis-Plus 的方案。

**问题**：依赖 Mac 地址和进程 PID，"虽然能做到尽量不重复，但仍有小几率"。

### 3.3 标识位分配两方案

**预分配**：上线前统计节点数人工申请。无开发量，适合节点固定/项目少的场景，**解决不了动态扩容**。

**动态分配**：标识位存放 Redis/Zookeeper/MySQL，服务启动时请求标识位，请求后更新为下一个可用的。

**关键设计问题——服务内唯一 vs 全局唯一**：以 Redis 举例，服务内唯一用自己项目的 Redis 即可；全局唯一则所有应用共用同一 Redis 节点。"如果没有全局唯一的需求，最好使 ID 服务内唯一，因为这样可以避免单点问题。"

### 3.4 Redis + Lua 动态分配实现

Redis 存储 Hash 结构 Key（`snowflake_work_id_key`），含 dataCenterId 和 workerId 两个键值对。应用启动时通过 **Lua 脚本**获取标识位（Lua 保证原子性）：

1. 首个节点获取时 Hash 可能不存在 → 先判断，不存在则初始化（dataCenterId、workerId 为 0）；
2. Hash 已存在，判断 dataCenterId、workerId 是否等于最大值 31 → 满足则初始化为 0 返回；
3. dataCenterId 和 workerId 排列组合共 1024，**先分配 workerId**；
4. 判断 workerId != 31 → 自增 workerId 返回；workerId = 31 → 自增 dataCenterId 并将 workerId 置 0。

标识位一直向下推进形成**环状**，通过 Lua 原子性保证 1024 节点下生成不重复。**超过 1024 节点**则需扩展标识位（如扩展 10bit）或选用开源框架。

## 4. 开源分布式 ID 框架

- **美团 Leaf**（github.com/Meituan-Dianping/Leaf）：实现雪花算法，额外提供**号段模式**；
- **百度 Uid**（github.com/baidu/uid-generator）。

**结论**：雪花算法可以满足大部分场景，"如无必要，不建议引入开源方案增加系统复杂度"。如果要求全局唯一且节点超出 1024，可修改算法组成（扩展标识位）或选 Leaf/Uid。
