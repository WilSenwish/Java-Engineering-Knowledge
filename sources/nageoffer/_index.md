## 1. Ragent AI（/ragent）✅ 开源

> **定位**：从 0 到 1 纯手工打造企业级 Agentic RAG，拒绝 Demo 玩具。面向 Agentic RAG 演进的生产级 Java AI 应用平台，覆盖从文档入库到智能问答的完整链路。
> **开源地址**：https://github.com/nageoffer/ragent

**核心能力**：
- 混合检索：向量、关键词、知识图谱、联网搜索并行召回，支持去重、RRF 融合与 Rerank
- 问题理解：查询词映射、问题重写与拆分、树形意图识别、多知识库路由
- 模型与工具：模型档位、首包探测、熔断降级，AgentScope 的 MCP 工具发现与调用
- 会话记忆：最近 N 轮消息 + 持久化摘要，控制 Token 成本并保留关键上下文
- 流量保护：Redis 公平排队与分布式并发控制
- 知识闭环：可编排入库 Pipeline、远程刷新、回答溯源、用户反馈、Trace 和管理后台

**架构**：前后端分离模块化单体，后端 7 个 Maven 模块：
- `infra-ai`：Chat/Embedding/Rerank/VLM 模型客户端、模型档位、路由、首包探测、健康状态与降级
- `system`：用户认证与审计日志
- `rag`：RAG 问答、知识库、入库 Pipeline、意图树、检索、会话及管理端 API
- `agent`：AgentScope ReAct 执行引擎，接入知识检索与 MCP 工具，支持技能、记忆和人工确认
- `bootstrap`：启动装配层
- `framework`：统一响应与异常、幂等、分布式 ID、MQ 适配、SSE 与跨节点流式取消
- `mcp-server`：基于 MCP Java SDK 的独立工具示例服务

**v1 vs v2**：v1 是 Workflow 编排（路径写死）；v2 是 Agentic 架构（ReAct 循环，路径由模型自己定）。两套并存：问答类走 v1 更快可控，要规划要动手操作的场景交给 v2。

**生产级特性**：
- 流量保护：Redis ZSET 公平排队 + Lua 原子抢占 + 过期信号量 + Pub/Sub 唤醒
- 模型容错：多候选模型自动切换，首包超时/空响应/异常触发降级，三态熔断
- 检索稳定性：多通道并行检索，单通道失败不影响主链，按召回/Rerank/TopK 分层控制
- 数据一致性：RocketMQ 事务消息保障分块可靠执行，幂等，远程刷新用分布式锁+状态机
- 可观测：Trace Run/Node 耗时、输入输出和异常；Langfuse 追踪推理、工具调用、Token
- 流式体验：SSE 分事件输出思考/正文/来源/推荐问题，全局超时及客户端断开取消
- 安全基础：Sa-Token 认证、数据归属校验、上传限流、参数校验

**设计模式实战**（每个模式对应具体问题）：策略（检索通道/结果后处理）、工厂（意图树/分块策略）、模板方法（并行检索/模型请求）、注册表（意图节点）、装饰器（向量写入同步关键词和图谱索引）、责任链（检索后处理/模型故障降级）、中间件（Agent 记忆注入/上下文压缩）、适配器（多模型方言/MQ 客户端）、状态机（远程文档定时刷新）、事件回调（流式响应/SSE）、AOP（链路追踪/幂等/审计）。

**技术栈**：Spring Boot 4 + Java 21 + React 18 + Redis + RocketMQ + ES/向量库 + Langfuse。

**常见误区（面试考点）**：① 调个 API 不算会 RAG/Agent（文档切分、召回率、多路融合、幻觉控制、工具选错处理才是追问点）；② RAG 不只是检索+生成（数据处理/分块策略/问题重写/意图识别/检索策略/会话记忆/任务执行每环都有坑）；③ 接入框架和 MCP 不等于企业级（增量更新、多租户隔离、高并发检索、成本控制、请求风控、负载均衡、工具参数校验、可观测性）；④ 不能只关注模型忽略工程能力（检索策略/Prompt/分块粒度/工具选择/上下文管理决定最终效果）。

## 2. oneThread 动态线程池（/onethread）❌ 星球专属

> **定位**：基于配置中心构建的动态可观测 Java 线程池框架，弥补 JDK 原生线程池参数配置不灵活的不足。作者曾写 Hippo4j（3.8k+ Star）。

**核心能力**：核心参数在线动态调整、运行时状态监控、阈值告警；兼容 Nacos、Apollo，实现参数热更新与统一管理。

**解决的痛点**（参考美团 2020 文章）：
- **任务执行拒绝**：核心数设置偏小导致大量 RejectedExecutionException 触发降级；
- **任务执行时间过长**：队列设置过长导致最大线程数失效，任务堆积、下游超时。

**技术实现**：
- 动态参数刷新：模板方法模式复用刷新逻辑，统一注册处理多种配置中心监听事件；
- 拒绝策略增强：基于 JDK InvocationHandler 动态代理拦截拒绝任务事件并告警；
- 监控告警：Prometheus + Grafana 采集可视化 + 钉钉通知，队列/活跃线程阈值告警；
- 优雅关闭线程池避免任务丢失。

**配置示例**：

```yaml
onethread:
  executors:
    - thread-pool-id: onethread-producer
      core-pool-size: 12
      maximum-pool-size: 18
      queue-capacity: 2000
      work-queue: ResizableCapacityLinkedBlockingQueue
      rejected-handler: CallerRunsPolicy
      keep-alive-time: 60
      allow-core-thread-time-out: false
      alarm:
        enable: true
        queue-threshold: 80
        active-threshold: 80
```

**项目结构**：core（核心）+ starter（可插拔配置中心组件：nacos/apollo/common/dashboard/web 适配层）+ spring-base（Spring 扫描/开关/Banner）+ example + dashboard-dev（可视化控制台）。

**技术栈**：Spring、Spring Boot、JUC、Tomcat、Jetty、Nacos、Apollo、Prometheus、Grafana。后端核心代码 1.34w 行（含注释），纯代码 4.99k 行。

## 3. oneCoupon 牛券（/onecoupon）❌ 星球专属

> **定位**：高性能优惠券系统，最大特点是能够承受近十万次查询和分发请求的高并发压力。项目代号"牛券"。

**业务架构**：券归属（平台券/店铺券）× 券类型（折扣券/满减券/立减券）+ 领取使用限制规则。

**技术栈**：JDK 17 + Spring Boot 3 + Maven 多 Modules；SpringCloudAlibaba/Nacos（可选开关）、Sentinel、Skywalking、RocketMQ 5.x、ElasticSearch、Redis、MySQL 5.7.x、EasyExcel、XXL-Job、Redisson、ShardingSphere。

**核心功能模块**：
1. **兑换/秒杀优惠券**：两种完全不同的秒杀方式，讲清区别和适用场景；
2. **分发用户优惠券**：平台/商家批量推送 + 基于 Excel 文件分发；EasyExcel 解决常规解析内存过高和 OOM；v1 单条 → v2 批量分发性能对比；
3. **创建优惠券模板**：责任链设计模式、优雅记录操作日志、缓存预热；
4. **分库分表**：ShardingSphere 大量应用（分表 + 分库逻辑）；
5. **防重复提交**：从业务代码抽象到 SpringBoot Starter，Spring AOP + 注解，Jmeter 和单元测试演示复现；
6. **解析 Excel 行数**：两个主流框架解析 100w 行 Excel 的性能对比；
7. **缓存击穿/穿透**：绝对企业级解决方案；**幂等逻辑**：Web 端防重 + MQ 防重复消费；Redis 内存淘汰策略选型。

**课程结构**：34 小节——项目背景和规范（01-04）、后台管理服务（05-15：责任链创建模板/ShardingSphere/日志组件/分布式锁防重/RocketMQ5.x 延时消息/EasyExcel 百万解析/线程池和延时队列优化/模板方法/XXL-Job）、分发&引擎服务（15-27：缓存击穿穿透/淘汰策略/分发/策略模式消息/去重表防重/兑换秒杀/锁定核销退还/百万预约/预约提醒）、结算服务（28-29：多线程列表/订单扣减金额计算）、面试服务（30-34：各项压测 + 简历编写）。

## 4. 12306 智能铁路购票平台（/12306）✅ 开源 1.5w+ Star

> **定位**：铁路 12306 智能购票系统，让学生快速掌握分布式系统设计技巧，适合对高并发、分布式感兴趣的同学。GitHub/Gitee 双开源。

**服务集合**：会员、购票、订单、支付、网关。**双版本**：
- SpringBoot 聚合服务版本：适合测试和部署（直接启动 aggregation-service 聚合服务 + 网关）；
- SpringCloud 微服务版本：适合学习微服务设计（支付、订单、用户、购票、网关分别启动）。

**技术架构**：JDK17 + SpringBoot3 + SpringCloud 微服务；含缓存、消息队列、分库分表、设计模式。

**项目难点与亮点**（面试素材）：
- **用户服务**：注册/添加乘车人信息真实性校验；大规模用户和乘车人数据分库分表（分片键选择、平滑上线、快速回滚）；多方式登录（用户名/手机号/邮箱）无法确定分片键的"读请求扩散"问题；高并发注册场景缓存穿透（缓存 Null 和布隆过滤器都有漏洞，如何解决）；敏感信息（姓名/手机号/邮箱/证件号/住址）防泄露；
- **购票服务**：座位分配逻辑（先查余票 → 遍历有余票车厢 → 优先相邻座位 → 次选同车厢不相邻 → 最后不同车厢不相邻）；
- **业务误区**：
  - 车次查询你以为用 ElasticSearch，实际上海量并发时 ES 并发能力和资源占用不适用，查询条件可通过 Redis 缓存内存组装；
  - 买北京南到南京南你以为只扣这一趟，实际会扣减北京南-济南西、北京南-南京南、济南西-南京西三趟，任一不满足都不成功；
  - 恶意刷中间站票：每个站数间数量有规则，动态放票（初期大站多票、临近发车开放小站票）。

**项目文档**：100+ 核心技术文档（快速开始、核心技术文档、从零到一开发三部分）。

## 5. Link SaaS 短链接平台（/shortlink）✅ 开源

> **定位**：SaaS 短链接系统，承载高并发和海量存储等场景难题。在线演示：http://shortlink.magestack.cn

**核心原理**：为长链接生成唯一短码（哈希/Base62/随机数/雪花ID + 碰撞校验）→ 建立"短码 ↔ 长链"映射并持久化（Redis + MySQL，支持去重、过期、权限）→ 构造短链 → 访问时根据短码查表 301/302 重定向 → 埋点统计（PV/UV、IP、来源、地区、设备/浏览器）。

**业务价值**：提升用户体验与转化；节省展示空间（微博/短信/通知字符受限场景）；品牌与美观统一（统一短链域名）；可观测可量化（A/B 测试与投放优化）；精细化运营（有效期、白黑名单、频控风控、防刷、二维码海报）。

**SaaS 工程挑战**：海量并发（响应时延与吞吐）、海量存储（冷热分层、缓存协同）、多租户（数据隔离/性能隔离/安全合规）、数据安全（敏感信息保护/访问控制/审计日志）、可扩展可伸缩（水平扩展）。

**性能实测**（阿里云 PTS）：
- TPS：短链接创建接口峰值 **12k/s**
- QPS：短链接跳转接口峰值 **56k/s**

**技术栈**：JDK17 + SpringBoot3 + SpringCloud 微服务。随课交付：精美前端控制台、工程化落地（架构设计、分库分表、缓存治理、监控告警、风控限流、可观测、上线运维）。配套 110+ 节实战视频（20-30 小时），代码现场从零编写。
