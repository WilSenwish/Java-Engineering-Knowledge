## 1. 项目定位

oneCoupon 寓意为一个优惠券系统，代号"牛券"。**高性能优惠券系统，能够承受近十万次查询和分发请求的高并发压力**。与网上其他优惠券系统的区别即在于此。

项目旨在帮助校招和社招的同学掌握足够的亮点。代码实现优雅，"甚至细致到参数定义都蕴含深意"。定位为继 12306、SaaS 短链接之后的"面试新宠项目"。

**注意：牛券项目不再实行开源策略**，仅加入知识星球的同学可学习（GitCode 仓库权限开通）。面试用牛券项目的同学会少很多——差异化亮点。

## 2. 业务架构

每个平台都离不开优惠券。优惠券分为**平台券和店铺券**；券类型分为**折扣券、满减券、立减券**；领取和使用均有限制规则。

## 3. 技术架构

JDK 17 + Spring Boot 3，组件库版本大多最新。

**技术栈全景**：SpringBoot 3、SpringCloudAlibaba、Nacos（可选开关）、Sentinel、Skywalking、RocketMQ 5.x、ElasticSearch、Redis、MySQL 5.7.x、EasyExcel、XXL-Job、Redisson、ShardingSphere。

**前置技术要求（重要）**：
- 强依赖只有 **分布式缓存 Redis** 和 **消息队列 RocketMQ**，其他框架"知道是做什么、会使用 API 即可满足开发条件，不需要深入原理"；
- 需要至少做过一个 SpringBoot 项目（点评/外卖/SaaS 短链接）；
- 本地只需启动 5.7.x MySQL（星球提供 Redis/RocketMQ 云中间件）。

**SpringCloud 可选开关**：不想学 SpringCloud 的话默认配置不开启（如 Nacos），想学时修改开关即可。

## 4. 七大项目亮点

### 4.1 兑换/秒杀优惠券

"项目里没点秒杀逻辑，都不好意思说是高并发系统"。牛券中针对高频优惠券会有较热流量。**利用两种完全不同的秒杀方式**，详细介绍两者的区别和对应的优惠券类型，"让大家能够在合适的业务使用适合的架构方案"。

### 4.2 分发用户优惠券

平台通过批量发送优惠券主动推送给用户以提升销售额。开发了**基于 Excel 文件的优惠券分发功能**。常规 Excel 解析常导致内存占用过高和 OOM，采用 **EasyExcel** 解决。**v1 版本单条分发 → v2 批量分发**，直观展示性能差距。

### 4.3 创建优惠券模板

"很多同学都说后台增删改查没什么技术含量，在我看来其实并不是。"以创建优惠券模板为例，虽是后管简单创建流程、基本算不上并发，但涉及：
- **责任链设计模式**
- **优雅记录操作日志**
- **缓存预热**

"如果把这些技能学会，可以很好应用到自己项目当中，增加代码的健壮性和可扩展。"

### 4.4 分库分表

"现阶段但凡上点体量的公司，都得在分库分表和分布式数据库上进行抉择。"作者认为分布式数据库相对不足（个人看法）：
- **兼容性**：部分分布式数据库不能 100% 兼容 MySQL，业务无法平滑迁移；
- **技术储备**：需要分布式数据库专家，"平常使用谁都可以，线上出现了问题不知道怎么解决才是致命"；
- **使用成本**：阿里云腾讯云无开源版本，付费版成本偏高；TiDB 开源版 Issue BUG 较多。

结论：以 **ShardingSphere** 为代表的分库分表框架"依然抗打"。牛券中大量应用，**不仅局限于分表，更会操作分库逻辑**。

### 4.5 防重复提交

"如果涉及到多场景通用代码，写到业务里只是第一步，更重要的是能够掌握抽象的能力。"先讲如何写到业务，**然后再抽象到基础组件 SpringBoot Starter**，Spring AOP 和注解必不可少。通过 **Jmeter 和单元测试**演示问题如何出现、如何复现。

### 4.6 解析 Excel 行数

"很多项目是以讲解功能为目的……而不说为什么要使用？"牛券中先通过市场主流框架铺垫、讲解有什么问题，再说最终方案的优点。**两个主流框架解析 100w 行记录的 Excel 获取行数，存在巨大性能差异**（原文配对比图）。

### 4.7 更多亮点

- **缓存击穿、穿透**："绝对企业级解决方案，基本上牛券里的方案可以说是在当下环境下最为合适的"；
- **幂等逻辑**：Web 端 API 接口防重复提交 + 消息队列防止重复消费，"掰开揉碎进行讲解"；
- **线上配置**：Redis 淘汰策略等"最适合项目的"配置讲解；
- 其他未完全统计亮点。

## 6. 项目结构&分支

标准基于 Maven 的 SpringBoot 多 Modules 项目，**拆分通用基础组件避免技术类重复定义**。包结构"适用于绝大部分场景"。

**分支策略（学习设计）**：
- `main`：完整代码分支；
- **从零到一分支**：按课程目录形式组织，"跟着写代码或者看的时候，能够做到绝对的循序渐进"。

## 7. 常见问题

- **适合人群**：简历不容易过筛/项目缺少亮点/平常 CRUD 想开拓视野/想学复杂场景解决方案；
