# Java并发常见面试题总结（上）

> 覆盖线程基础、线程生命周期、多线程、死锁四大部分。

## 线程

### ⭐️ 什么是线程和进程？

#### 何为进程？

进程是程序的一次执行过程，是系统运行程序的基本单位，因此进程是动态的。系统运行一个程序即是一个进程从创建、运行到消亡的过程。

在 Java 中，启动 main 函数其实就是启动了一个 JVM 的进程，而 main 函数所在的线程就是这个进程中的一个线程，也称主线程。

#### 何为线程？

线程是一个比进程更小的执行单位。一个进程在其执行过程中可以产生多个线程。与进程不同的是，同类的多个线程共享进程的**堆**和**方法区**资源，但每个线程有自己的**程序计数器**、**虚拟机栈**和**本地方法栈**，所以系统在产生一个线程或切换线程时，负担要比进程小得多，因此线程也被称为**轻量级进程**。

一个普通的 Java 程序运行的线程（通过 JMX/ThreadMXBean 查看）：

```plain
[5] Attach Listener    // 添加事件
[4] Signal Dispatcher  // 分发处理给 JVM 信号的线程
[3] Finalizer          // 调用对象 finalize 方法的线程
[2] Reference Handler  // 清除 reference 线程
[1] main               // main 线程,程序入口
```

**一个 Java 程序的运行是 main 线程和多个其他线程同时运行。**

### Java 线程和操作系统的线程有啥区别？

早期 JDK 曾使用绿色线程（Green Threads）实现用户级线程。后来，HotSpot 中通过 `new Thread()` 创建的传统线程采用**平台线程（Platform Thread）**实现，通常以 1:1 方式映射到操作系统线程，由操作系统负责调度。Java 21 正式引入的**虚拟线程（Virtual Thread）**由 JVM 调度，大量虚拟线程可以复用较少的平台线程作为载体，因此不能再把所有 Java 线程都等同于操作系统线程。

- 用户线程：由用户空间程序管理和调度的线程，运行在用户空间，创建和切换成本较低；能否利用多核取决于映射模型（多对一不能并行利用多核，多对多可以）。
- 内核线程：由操作系统内核管理和调度，运行在内核空间，创建和切换成本通常更高，可以直接利用多核。

常见线程模型：一对一、多对一、多对多。Windows/Linux 主流操作系统中，HotSpot 平台线程通常采用一对一模型；虚拟线程由 JVM 调度到一组平台线程上执行。

### ⭐️ 请简要描述线程与进程的关系、区别及优缺点？

一个进程中可以有多个线程，多个线程共享进程的**堆**和**方法区（JDK1.8 之后的元空间）**资源，但每个线程有自己的**程序计数器**、**虚拟机栈**和**本地方法栈**。

**线程是进程划分成的更小的运行单位。** 线程和进程最大的不同在于：各进程基本独立，而同一进程中的线程极有可能相互影响。线程执行开销小，但不利于资源管理和保护；进程正相反。

**为什么程序计数器、虚拟机栈和本地方法栈是线程私有的？**

- **程序计数器私有**：① 字节码解释器通过改变程序计数器依次读取指令，实现流程控制；② 多线程情况下记录当前线程执行的位置，线程切换回来时知道上次运行到哪。执行 native 方法时记录的是 undefined 地址。
- **虚拟机栈/本地方法栈私有**：每个 Java 方法执行前创建栈帧（局部变量表、操作数栈、常量池引用等），方法调用到完成对应栈帧入栈出栈；本地方法栈为 Native 方法服务（HotSpot 中与虚拟机栈合二为一）。私有是为了保证线程中的局部变量不被别的线程访问到。

**堆和方法区**是所有线程共享的资源：堆是进程中最大的一块内存，存放新创建的对象；方法区存放已加载的类信息、常量、静态变量、JIT 编译后的代码等。

### 如何创建线程？

继承 `Thread` 类、实现 `Runnable` 接口、实现 `Callable` 接口、使用线程池、使用 `CompletableFuture` 等。这些都属于 Java 代码中使用多线程的方法。**严格来说，Java 只有一种方式可以创建线程：通过 `new Thread().start()` 创建。**

### ⭐️ 说说线程的生命周期和状态？

Java 线程在生命周期指定时刻只可能处于 6 种状态之一：

- **NEW**：初始状态，线程被创建但未调用 `start()`。
- **RUNNABLE**：运行状态，调用 `start()` 等待运行。
- **BLOCKED**：阻塞状态，等待锁释放。
- **WAITING**：等待状态，等待其他线程做出特定动作（通知或中断）。
- **TIMED_WAITING**：超时等待状态，可在指定时间后自行返回。
- **TERMINATED**：终止状态，线程运行完毕。

> 操作系统层面线程有 READY 和 RUNNING 状态；JVM 层面只能看到 RUNNABLE 状态。Java 的 `Thread.State` 描述的是 JVM 层面的线程状态，不用于反映操作系统调度器的全部内部状态。

### 什么是线程上下文切换？

线程在执行过程中有自己的运行条件和状态（上下文），如程序计数器、栈信息等。出现以下情况线程会从占用 CPU 状态退出：

- 主动让出 CPU（`sleep()`、`wait()` 等）；
- 时间片用完（防止线程/进程长时间占用 CPU 导致饿死）；
- 调用了阻塞类型的系统中断（如请求 IO）；
- 被终止或结束运行。

前三种会发生线程切换：需要保存当前线程的上下文，留待下次占用 CPU 时恢复现场，并加载下一个线程的上下文。**上下文切换会占用 CPU、内存等系统资源，频繁切换会造成整体效率低下。**

### Thread#sleep() 方法和 Object#wait() 方法对比

**共同点**：两者都可以暂停线程的执行。

**区别**：

- `sleep()` 没有释放锁，`wait()` 释放了锁。
- `wait()` 通常用于线程间交互/通信，`sleep()` 通常用于暂停执行。
- `wait()` 被调用后线程不会自动苏醒，需要其他线程调用同一对象上的 `notify()`/`notifyAll()`；`sleep()` 执行完成后自动苏醒（或 `wait(long timeout)` 超时苏醒）。
- `sleep()` 是 `Thread` 类的静态本地方法，`wait()` 是 `Object` 类的本地方法。

### 为什么 wait() 方法不定义在 Thread 中？

`wait()` 是让获得对象锁的线程实现等待，会自动释放当前线程占有的对象锁。每个对象（`Object`）都拥有对象锁，既然要释放当前线程占有的对象锁并让其进入 WAITING 状态，自然是要操作对应的对象（`Object`）而非当前的线程（`Thread`）。

类似问题：**为什么 `sleep()` 定义在 `Thread` 中？** 因为 `sleep()` 是让当前线程暂停执行，不涉及对象锁。

### 可以直接调用 Thread 类的 run 方法吗？

不可以。`new Thread()` 后线程进入新建状态，调用 `start()` 会启动线程并使线程进入就绪状态，分配到时间片后开始运行，`start()` 会执行线程的相应准备工作然后自动执行 `run()` 的内容，这是真正的多线程工作。**直接执行 `run()` 会把 `run()` 当成一个普通方法在调用该方法的线程去执行，并不是多线程工作。**

## 多线程

### 并发与并行的区别

- **并发**：两个及以上的作业在同一**时间段**内执行。
- **并行**：两个及以上的作业在同一**时刻**执行。

最关键的点：是否是**同时**执行。

### 同步和异步的区别

- **同步**：发出一个调用之后，在没有得到结果之前，该调用就不可以返回，一直等待。
- **异步**：调用发出之后不用等待返回结果，该调用直接返回。

### ⭐️ 为什么要使用多线程？

**总体**：线程是轻量级进程，线程间切换和调度成本远小于进程；多核 CPU 时代多个线程可同时运行，减少上下文切换开销；百万级甚至千万级并发量的系统，多线程并发编程是开发高并发系统的基础。

**深入计算机底层**：

- **单核时代**：提高单进程利用 CPU 和 IO 系统的效率。只有一个线程时，线程被 IO 阻塞则整个进程被阻塞，CPU 和 IO 设备只有一个在运行，系统整体效率只有 50%；多线程时一个线程被 IO 阻塞，其他线程还可继续使用 CPU。
- **多核时代**：提高进程利用多核 CPU 的能力。复杂任务用多个线程可被映射到底层多个 CPU 核心上执行，效率显著提高，约等于（单核时执行时间 / CPU 核心数）。

### ⭐️ 单核 CPU 支持 Java 多线程吗？

支持。操作系统通过时间片轮转方式将 CPU 时间分配给不同线程。单核 CPU 一次只能执行一个任务，但通过快速切换让用户感觉多个任务同时进行。

操作系统两种线程调度方式：

- **抢占式调度（Preemptive Scheduling）**：操作系统决定何时暂停当前线程并切换到另一个，通常由系统时钟中断（时间片轮转）或高优先级事件（如 IO 完成）触发。存在上下文切换开销，但公平性和 CPU 利用率较好。**Java 使用的是抢占式调度**，JVM 本身不负责线程调度，而是委托给操作系统。
- **协同式调度（Cooperative Scheduling）**：线程执行完毕后主动通知系统切换到另一个线程。减少上下文切换开销，但公平性较差，容易阻塞。

### ⭐️ 单核 CPU 上运行多个线程效率一定会高吗？

取决于线程类型和任务性质：

- **CPU 密集型**：主要进行计算和逻辑处理，占用大量 CPU 资源。单核上多线程会导致频繁切换，增加开销，降低效率。
- **IO 密集型**：主要进行输入输出操作，等待 IO 响应而不占用太多 CPU。单核上多线程可以利用 CPU 等待 IO 时的空闲时间，提高效率。

对于单核 CPU：CPU 密集型任务开很多线程会影响效率；IO 密集型任务开很多线程会提高效率。"很多"也要适度，不能超过系统承受上限。

### 使用多线程可能带来什么问题？

并发编程的目的提高执行效率，但并不总是能提高运行速度，且可能遇到：**内存泄漏、死锁、线程不安全**等问题。

### 如何理解线程安全和不安全？

- **线程安全**：多线程环境下，对于同一份数据，不管有多少线程同时访问，都能保证数据的正确性和一致性。
- **线程不安全**：多线程环境下，多个线程同时访问同一份数据时可能导致数据混乱、错误或丢失。

## ⭐️ 死锁

### 什么是线程死锁？

多个线程同时被阻塞，它们中的一个或者全部都在等待某个资源被释放。由于线程被无限期阻塞，因此程序不可能正常终止。

死锁示例（线程 A 持有资源 2，线程 B 持有资源 1，同时都想申请对方的资源）：

```java
public class DeadLockDemo {
    private static Object resource1 = new Object();// 资源 1
    private static Object resource2 = new Object();// 资源 2

    public static void main(String[] args) {
        new Thread(() -> {
            synchronized (resource1) {
                System.out.println(Thread.currentThread() + "get resource1");
                try { Thread.sleep(1000); } catch (InterruptedException e) { e.printStackTrace(); }
                System.out.println(Thread.currentThread() + "waiting get resource2");
                synchronized (resource2) {
                    System.out.println(Thread.currentThread() + "get resource2");
                }
            }
        }, "线程 1").start();

        new Thread(() -> {
            synchronized (resource2) {
                System.out.println(Thread.currentThread() + "get resource2");
                try { Thread.sleep(1000); } catch (InterruptedException e) { e.printStackTrace(); }
                System.out.println(Thread.currentThread() + "waiting get resource1");
                synchronized (resource1) {
                    System.out.println(Thread.currentThread() + "get resource1");
                }
            }
        }, "线程 2").start();
    }
}
```

产生死锁的四个必要条件：

1. **互斥条件**：该资源任意时刻只由一个线程占用。
2. **请求与保持条件**：一个线程因请求资源而阻塞时，对已获得的资源保持不放。
3. **不剥夺条件**：线程已获得的资源在未使用完之前不能被其他线程强行剥夺。
4. **循环等待条件**：若干线程之间形成头尾相接的循环等待资源关系。

### 如何检测死锁？

- 使用 `jstack <pid>` 或 `jcmd <pid> Thread.print -l` 查看线程栈和并发锁信息，输出中会列出相关线程及其持有、等待的锁。`jmap` 主要用于查看堆信息或生成堆转储，不是死锁诊断工具。
- 采用 VisualVM、JConsole 等工具排查（JConsole 连接程序后进入线程界面选择"检测死锁"）。

### 如何预防和避免线程死锁？

**预防死锁**（破坏必要条件即可）：

1. **破坏请求与保持条件**：一次性申请所有的资源。
2. **破坏不剥夺条件**：占用部分资源的线程进一步申请其他资源时，如果申请不到，可以主动释放已占有的资源。
3. **破坏循环等待条件**：按序申请资源，释放资源则反序释放。

**避免死锁**：在资源分配时借助于算法（如银行家算法）对资源分配进行计算评估，使其进入安全状态。**安全状态**指系统能够按照某种线程推进顺序（P1、P2、P3……Pn）为每个线程分配所需资源，直到满足每个线程对资源的最大需求。
