# Java基础常见面试题总结(上)

> 本文是 JavaGuide Java 基础专题的面试复习入口，覆盖基础概念、基本语法、基本数据类型、变量、方法五大部分。

## 基础概念与常识

### Java 语言有哪些特点？

1. 简单易学（语法简单，上手容易）；
2. 面向对象（封装，继承，多态）；
3. 平台无关性（Java 虚拟机实现平台无关性）；
4. 支持多线程（C++ 语言没有内置的多线程机制，因此必须调用操作系统的多线程功能来进行多线程程序设计，而 Java 语言却提供了多线程支持）；
5. 可靠性（具备异常处理和自动内存管理机制）；
6. 安全性（Java 语言本身的设计就提供了多重安全防护机制如访问权限修饰符、限制程序直接访问操作系统资源）；
7. 高效性（通过 Just In Time 编译器等技术的优化，Java 语言的运行效率还是非常不错的）；
8. 支持网络编程并且很方便；
9. 编译与解释并存。

> **修正（issue#544）**：C++11 开始（2011 年），C++ 就引入了多线程库，在 Windows、Linux、macOS 都可以使用 `std::thread` 和 `std::async` 来创建线程。

🌈 拓展："Write Once, Run Anywhere" 这句宣传口号流传多年，至今仍有很多人觉得跨平台是 Java 最大的优势。实际上，跨平台已经不是 Java 最大的卖点了（Docker 等虚拟化技术很容易实现跨平台）。**Java 强大的生态才是。**

### Java SE vs Java EE

- **Java SE（Java Platform, Standard Edition）**: Java 平台标准版，Java 编程语言的基础，包含支持 Java 应用程序开发和运行的核心类库以及虚拟机等核心组件。可用于构建桌面应用程序或简单的服务器应用程序。
- **Java EE（Java Platform, Enterprise Edition）**: Java 平台企业版，建立在 Java SE 的基础上，包含支持企业级应用程序开发和部署的标准和规范（Servlet、JSP、EJB、JDBC、JPA、JTA、JavaMail、JMS）。可用于构建分布式、可移植、健壮、可伸缩和安全的服务端 Java 应用程序。

简单来说，Java SE 是 Java 的基础版本，Java EE 是 Java 的高级版本。Java SE 更适合开发桌面应用程序或简单的服务器应用程序，Java EE 更适合开发复杂的企业级应用程序或 Web 应用程序。

除 Java SE 和 Java EE 外，还有 **Java ME（Micro Edition）**，Java 的微型版本，主要用于开发嵌入式消费电子设备的应用程序（手机、PDA、机顶盒等），现已基本淘汰。

### ⭐️ JVM vs JDK vs JRE

#### JVM

Java 虚拟机（Java Virtual Machine, JVM）是运行 Java 字节码的虚拟机。JVM 有针对不同系统的特定实现（Windows、Linux、macOS），目的是使用相同的字节码，它们都会给出相同的结果。字节码和不同系统的 JVM 实现是 Java 语言"一次编译，随处可以运行"的关键所在。

**JVM 并不是只有一种！只要满足 JVM 规范，每个公司、组织或者个人都可以开发自己的专属 JVM。** 我们平时接触到的 HotSpot VM 仅仅是 JVM 规范的一种实现。除 HotSpot VM 外，还有 J9 VM、Zing VM、JRockit VM 等。

#### JDK 和 JRE

- **JDK（Java Development Kit）**：功能齐全的 Java 开发工具包，供开发者使用，用于创建和编译 Java 程序。包含 JRE，以及编译器 javac 和其他工具（javadoc、jdb、jconsole、javap 等）。
- **JRE（Java Runtime Environment）**：运行已编译 Java 程序所需的环境，主要包含两部分：① **JVM**；② **Java 基础类库（Class Library）**：一组标准的类库，提供常用的功能和 API（I/O 操作、网络通信、数据结构等）。

简单来说，JRE 只包含运行 Java 程序所需的环境和类库，而 JDK 不仅包含 JRE，还包括用于开发和调试 Java 程序的工具。

从 JDK 9 开始不再区分 JDK 和 JRE，取而代之的是模块系统（JDK 被重新组织成 94 个模块）+ jlink 工具（生成自定义 Java 运行时映像，仅包含给定应用程序所需的模块）。从 JDK 11 开始，Oracle 不再提供单独的 JRE 下载。

### ⭐️ 什么是字节码？采用字节码的好处是什么？

在 Java 中，JVM 可以理解的代码就叫做**字节码**（扩展名为 `.class` 的文件），它不面向任何特定的处理器，只面向虚拟机。Java 语言通过字节码的方式，在一定程度上解决了传统解释型语言执行效率低的问题，同时又保留了解释型语言可移植的特点。

需要格外注意的是 `.class -> 机器码` 这一步：以 HotSpot 为例，JVM 加载字节码后可以先解释执行，并识别经常调用的方法和代码块（热点代码），再由 **JIT（Just in Time Compilation）** 编译器将热点字节码编译为机器码。这也解释了为什么常说 **Java 是编译与解释共存的语言**。

HotSpot 采用惰性评估（Lazy Evaluation）：根据二八定律，消耗大部分系统资源的只有那一小部分代码（热点代码），JVM 会根据代码每次被执行的情况收集信息并相应优化，执行次数越多，速度越快。

### ⭐️ 为什么说 Java 语言"编译与解释并存"？

高级编程语言按程序执行方式分为两种：

- **编译型**：通过编译器将源代码一次性翻译成可被该平台执行的机器码，执行速度比较快，开发效率比较低（C、C++、Go、Rust）。
- **解释型**：通过解释器一句一句将代码解释为机器代码后再执行，开发效率比较快，执行速度比较慢（Python、JavaScript、PHP）。

Java 源码先由编译器生成字节码（`.class` 文件），字节码可由 JVM 解释执行，也可在运行时由 JIT 编译为机器码。字节码并非必须由解释器执行，具体执行策略由 JVM 实现决定。

### AOT 有什么优点？为什么不全部使用 AOT 呢？

JDK 9 曾通过 JEP 295 引入实验性 AOT 工具 `jaotc`，但已在 JDK 17 中移除。下文讨论的是一般意义上的 AOT，以及 GraalVM Native Image 等独立工具链。

| 对比维度 | JIT（即时编译） | AOT（提前编译） |
|---|---|---|
| **编译时机** | 运行时根据代码执行情况编译 | 构建阶段提前编译 |
| **启动与预热** | 启动后通常需要解释执行和编译热点代码 | 通常启动更快，不需要等待 JIT 预热 |
| **长期运行性能** | 可以利用运行时采集的信息持续优化热点代码 | 缺少完整的运行时信息，具体表现取决于实现和构建配置 |
| **运行时内存** | 需要保存编译器、性能数据和生成的机器码 | Native Image 等实现通常占用更少的运行时内存 |
| **运行依赖** | 需要 JVM 和相应运行时 | Native Image 可以生成独立的本地可执行文件 |
| **动态特性** | 支持运行时加载、反射和字节码生成 | 闭世界分析工具通常需要元数据或构建期处理 |
| **常见场景** | 长时间运行、重视持续吞吐量的服务 | CLI、Serverless、弹性扩缩容和冷启动敏感的服务 |

AOT 的优势主要体现在启动速度和运行时内存占用，适合冷启动频繁、实例生命周期较短或需要快速扩容的应用。JIT 则能根据运行时收集的信息优化热点代码，长时间运行的服务通常更容易发挥这方面的优势。

**为什么不全部使用 AOT？** 以 GraalVM Native Image 为例，它在构建本地可执行文件时会进行**闭世界分析**：构建器从程序入口出发，分析哪些类、方法和字段可能在运行时被访问，只把可达代码和必要的元数据放进最终产物。反射、动态代理和 JNI 仍然可以使用，但静态分析无法推断的动态访问通常需要**可达性元数据**，提前声明运行时可能访问的类、方法、字段、代理接口和 JNI 元素。

AOT 把一部分运行时工作和信息搬到了构建阶段，同时增加了构建时间、元数据维护和兼容性适配成本。对于依赖运行时动态加载、Java Agent 或大量动态字节码生成的应用，JIT 模式通常更省事。

### Oracle JDK vs OpenJDK

2006 年 SUN 公司将 Java 开源，也就有了 OpenJDK。2009 年 Oracle 收购了 Sun 公司，基于 OpenJDK 构建了 Oracle JDK。

区别总结：

1. **是否开源**：OpenJDK 是完全开源的参考模型；Oracle JDK 基于 OpenJDK 实现，并不是完全开源的。
2. **是否免费**：Oracle JDK 的许可取决于具体版本。Oracle JDK 21 及之后的特定更新在 NFTC 有效期内允许包括商业生产在内的免费使用（JDK 21 更新 NFTC 至 2026 年 9 月，JDK 25 更新至 2028 年 9 月）。Oracle 的 OpenJDK 构建使用 GPLv2 + Classpath Exception。
3. **功能性**：Java 11 之后，Oracle JDK 和 OpenJDK 的功能基本一致。
4. **长期支持**：Java 8、11、17、21、25 是 Oracle LTS 版本，计划未来每两年发布一个 LTS。
5. **协议**：BCL 仅用于 2019 年 4 月 16 日之前发布的版本；OTN 协议（11 及之后）可以自己私下用，但商用需要付费。

**选择建议**：选择 OpenJDK 或基于 OpenJDK 的发行版（AWS Amazon Corretto、阿里巴巴 Alibaba Dragonwell）。

### Java 和 C++ 的区别？

- Java 不提供指针来直接访问内存，程序内存更加安全
- Java 的类是单继承的，C++ 支持多重继承；Java 的类不可以多继承，但接口可以多继承
- Java 有自动内存管理垃圾回收机制（GC），不需要程序员手动释放无用内存
- C++ 同时支持方法重载和操作符重载，Java 只支持方法重载

## 基本语法

### 注释有哪几种形式？

1. **单行注释**：通常用于解释方法内某单行代码的作用。
2. **多行注释**：通常用于解释一段代码的作用。
3. **文档注释**：通常用于生成 Java 开发文档。

注释不会执行（编译器编译前会抹掉所有注释，字节码中不保留注释）。《Clean Code》指出：**代码的注释不是越详细越好，好的代码本身就是注释，要尽量通过代码来阐述。**

### 标识符和关键字的区别是什么？

- **标识符**：给程序、类、变量、方法等取的名字，简单来说就是一个名字。
- **关键字**：被 Java 语言赋予特殊含义的标识符，只能用于特定的地方。

### Java 语言关键字有哪些？

| 分类 | 关键字 |
|---|---|
| 访问控制 | private, protected, public |
| 类、方法和变量修饰符 | abstract, class, extends, final, implements, interface, native, new, static, strictfp, synchronized, transient, volatile, enum |
| 程序控制 | break, continue, return, do, while, if, else, for, instanceof, switch, case, default, assert |
| 错误处理 | try, catch, throw, throws, finally |
| 包相关 | import, package |
| 基本类型 | boolean, byte, char, double, float, int, long, short |
| 变量引用 | super, this, void |
| 保留字 | goto, const |

所有关键字都是小写的。`true`、`false`、`null` 看起来像关键字，但实际上是字面值。

### ⭐️ 自增自减运算符

`++` 和 `--` 可以放在变量之前或之后：

- **前缀形式**（`++a`）：先自增/自减，再使用。`b = ++a` 先将 a 增加 1，再把增加后的值赋给 b。
- **后缀形式**（`a++`）：先使用当前值，再自增/自减。`b = a++` 先将 a 的当前值赋给 b，再将 a 增加 1。

口诀：**符号在前就先加/减，符号在后就后加/减**。

```java
int a = 9;
int b = a++;   // b = 9,  a = 10
int c = ++a;   // a = 11, c = 11
int d = c--;   // d = 11, c = 10
int e = --d;   // d = 10, e = 10
// 结果：a = 11、b = 9、c = 11、d = 10、e = 10
```

### ⭐️ 移位运算符

三种移位运算符：

- `<<`：左移，高位丢弃，低位补零。`x << n` 相当于 x 乘以 2 的 n 次方（不溢出时）。
- `>>`：带符号右移，高位补符号位，低位丢弃。`x >> n` 相当于 x 除以 2 的 n 次方。
- `>>>`：无符号右移，忽略符号位，空位以 0 补齐。

使用移位运算符的主要原因：① **高效**（直接对应处理器移位指令，通常一个时钟周期完成）；② **节省内存**（可用一个整数存储多个布尔值/标志位）。

应用场景：位字段管理、哈希算法和加密解密、数据压缩（霍夫曼编码）、数据校验（CRC）、内存对齐。

注意：

- `double`、`float` 不能进行移位操作。
- 实际支持的类型只有 `int` 和 `long`，`short`、`byte`、`char` 移位前会转换为 `int`。
- int 移位位数 ≥ 32 时先求余（32%32=0，即不移位；42%32=10）；long 的基数是 64。

`HashMap`（JDK1.8）的 `hash` 方法就用到了移位运算符：

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

### continue、break 和 return 的区别是什么？

1. `continue`：跳出当前的这一次循环，继续下一次循环。
2. `break`：跳出整个循环体，继续执行循环下面的语句。
3. `return`：跳出所在方法，结束该方法的运行。`return;` 用于无返回值方法；`return value;` 用于有返回值方法。

## ⭐️ 基本数据类型

### Java 中的几种基本数据类型？

8 种：6 种数字类型（4 种整数型 `byte`/`short`/`int`/`long`，2 种浮点型 `float`/`double`）、1 种字符类型 `char`、1 种布尔型 `boolean`。

| 基本类型 | 位数 | 字节 | 默认值 | 取值范围 |
|---|---|---|---|---|
| `byte` | 8 | 1 | 0 | -128 ~ 127 |
| `short` | 16 | 2 | 0 | -32768 ~ 32767 |
| `int` | 32 | 4 | 0 | -2147483648 ~ 2147483647 |
| `long` | 64 | 8 | 0L | -9223372036854775808 ~ 9223372036854775807 |
| `char` | 16 | 2 | '\u0000' | 0 ~ 65535 |
| `float` | 32 | 4 | 0f | 约 ±3.4E38，另含 ±0、±∞、NaN |
| `double` | 64 | 8 | 0d | 约 ±1.8E308，另含 ±0、±∞、NaN |
| `boolean` | 未规定 | 未规定 | false | true、false |

整型最大正数都减 1 的原因：二进制补码表示法中最高位表示符号位，要表示最大正数需把除最高位外所有位设为 1，再加 1 就会溢出变成负数。

`boolean` 官方文档未明确定义大小，依赖于 JVM 厂商实现。逻辑上理解占用 1 位，实际中会考虑计算机高效存储因素。

Java 每种基本类型所占存储空间的大小不会随机器硬件架构变化而变化，这是 Java 程序更具可移植性的原因之一。

注意：

1. 整数字面量默认按 `int` 解析，超范围或显式 `long` 需加 **L**。
2. 带小数点或指数的浮点字面量默认是 `double`，赋给 `float` 需加 **f/F**。
3. `char` 用单引号，`String` 用双引号。

### 基本类型和包装类型的区别？

- **用途**：包装类型可用于泛型，基本类型不可以。
- **存储方式**：基本数据类型的局部变量保存在当前栈帧的局部变量表中，实例字段属于对象状态；包装类型属于对象类型，实例通常分配在堆中（JIT 可能通过逃逸分析和标量替换消除实际分配）。
- **占用空间**：基本数据类型占用空间往往非常小。
- **默认值**：成员变量包装类型不赋值就是 `null`，基本类型有默认值。
- **比较方式**：基本类型 `==` 比较值；包装类型 `==` 比较引用，比较数值应使用 `equals()`。

⚠️ **基本数据类型存放在栈中是一个常见的误区！** 存储位置取决于变量种类：局部变量在栈帧局部变量表，实例字段在堆中对象内，静态字段属于类（JDK 8 及之后 HotSpot 中位于 Java 堆）。

### 包装类型的缓存机制？

`Byte`、`Short`、`Integer`、`Long` 默认创建数值 **[-128, 127]** 的缓存数据，`Character` 创建 **[0, 127]** 范围缓存，`Boolean` 直接返回预定义实例。`Integer` 可通过 `-XX:AutoBoxCacheMax=<size>` 修改缓存上限（不能改下限 -128）。`Float`、`Double` 没有缓存机制。

```java
Integer i1 = 33;
Integer i2 = 33;
System.out.println(i1 == i2);  // true（缓存）

Float i11 = 333f;
Float i22 = 333f;
System.out.println(i11 == i22);  // false

Integer i1 = 40;               // 装箱 → Integer.valueOf(40)，走缓存
Integer i2 = new Integer(40);  // 直接创建新对象
System.out.println(i1 == i2);  // false
```

**记住：所有整型包装类对象之间值的比较，全部使用 equals 方法。**

### 自动装箱与拆箱？原理是什么？

- **装箱（Boxing）**：将基本类型用它们对应的引用类型包装起来。
- **拆箱（Unboxing）**：将包装类型转换为基本数据类型。

```java
Integer i = 10;  // 装箱，等价于 Integer i = Integer.valueOf(10)
int n = i;       // 拆箱，等价于 int n = i.intValue()
```

从字节码看，装箱调用包装类的 `valueOf()` 方法，拆箱调用 `xxxValue()` 方法。**频繁拆装箱会严重影响系统性能，应尽量避免。**

```java
private static long sum() {
    Long sum = 0L;  // 应该使用 long 而不是 Long
    for (long i = 0; i <= Integer.MAX_VALUE; i++)
        sum += i;   // 每次循环都触发拆箱+装箱
    return sum;
}
```

### 为什么浮点数运算的时候会有精度丢失的风险？

计算机使用有限位宽的二进制格式表示 `float` 和 `double`，许多十进制小数转换为二进制后会无限循环，只能舍入为有限位数，因此存在精度损失。像 0.5、0.25 这样能表示为有限二进制小数的值可以被精确表示。

```java
float a = 2.0f - 1.9f;
float b = 1.8f - 1.7f;
System.out.printf("%.9f", a);  // 0.100000024
System.out.println(b);         // 0.099999905
System.out.println(a == b);    // false
```

### 如何解决浮点数运算的精度丢失问题？

`BigDecimal` 可以精确表示十进制数，并提供可显式指定精度和舍入规则的运算。大部分需要十进制精确运算的业务场景（如涉及钱的场景）都使用 `BigDecimal`。

```java
BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");
BigDecimal c = new BigDecimal("0.8");

BigDecimal x = a.subtract(c);  // 0.2
BigDecimal y = b.subtract(c);  // 0.20
System.out.println(Objects.equals(x, y));      // false（比较内容）
System.out.println(0 == x.compareTo(y));       // true（比较值）
```

### 超过 long 整型的数据应该如何表示？

`BigInteger` 内部使用 `int[]` 数组来存储任意大小的整型数据，相对于常规整数类型运算效率会相对较低。

## 变量

### ⭐️ 成员变量与局部变量的区别？

- **语法形式**：成员变量属于类，局部变量定义在代码块/方法中或作为方法参数；成员变量可以被访问控制修饰符及 `static` 修饰，局部变量不能；两者都能被 `final` 修饰。
- **存储方式**：`static` 修饰的成员变量属于类，否则属于实例；实例字段是对象状态的一部分，方法参数和局部变量保存在当前栈帧的局部变量表中。
- **生存时间**：成员变量随对象创建而存在，局部变量随方法调用自动生成、随方法调用结束消亡。
- **默认值**：成员变量未被赋值时自动以类型默认值赋值（`final` 修饰的必须显式赋值），局部变量不会自动赋值。

**为什么成员变量有默认值？** JLS 规定，类变量、实例变量和数组元素在创建时会被初始化为各自类型的默认值；局部变量受"明确赋值"（definite assignment）规则约束，读取前编译器必须能够确定它已被赋值。

### 静态变量有什么作用？

被 `static` 修饰的变量可被类的所有实例共享，无论创建多少对象都共享同一份，只分配一次内存，节省内存。通过类名访问（`StaticVariableExample.staticVar`）。通常情况下，静态变量会被 `final` 修饰成为常量。

### 字符型常量和字符串常量的区别？

- **形式**：字符常量是单引号引起的一个字符；字符串常量是双引号引起的 0 个或若干个字符。
- **含义**：字符常量是一个 `char` 值，表示 UTF-16 代码单元，可参与数值运算；字符串常量是对 `String` 对象的引用。
- **占用空间**：`char` 值是 16 位无符号整数（2 字节）；`String` 对象的内存占用属于 JVM 实现细节。

## 方法

### 什么是方法的返回值？

方法的返回值是指方法体中的代码执行后产生的结果，作用是接收结果以便用于其他操作。按返回值和参数类型分为：无参无返回值、有参无返回值、有返回值无参、有返回值有参四种。

### 静态方法为什么不能调用非静态成员？

静态方法在静态上下文中执行，没有隐式的当前实例 `this`，因此不能直接访问实例成员。静态方法仍可以通过显式的对象引用访问该对象的实例成员，与类加载或成员是否已"分配内存"无关。

### ⭐️ 静态方法和实例方法有何不同？

1. **调用方式**：外部调用静态方法可用 `类名.方法名` 或 `对象.方法名`；实例方法只能用 `对象.方法名`。一般建议使用 `类名.方法名` 调用静态方法（避免混淆，静态方法不属于某个对象而属于这个类）。
2. **访问类成员是否存在限制**：静态方法只允许访问静态成员，不允许访问实例成员；实例方法无此限制。

### ⭐️ 重载和重写有什么区别？

**重载（Overloading）**：同一个类中（或父子类之间）多个同名方法，方法名相同，参数类型/个数/顺序不同，返回值和访问修饰符可以不同。编译器通过用各个方法给出的参数类型与特定方法调用所使用的值类型进行匹配来挑选出相应的方法（重载解析）。

**重写（Overriding）**：子类对父类可访问实例方法的重新实现。方法名、参数列表必须相同；子类返回值类型应比父类更小或相等；抛出异常范围小于等于父类；访问修饰符范围大于等于父类。`private`/`final`/`static` 修饰的父类方法不能被重写（`static` 方法可被再次声明）。构造方法无法被重写。运行期发生动态分派。

| 区别点 | 重载 (Overloading) | 重写 (Overriding) |
|---|---|---|
| **发生范围** | 同一个类中 | 父类与子类之间 |
| **方法签名** | 方法名相同，参数列表必须不同 | 方法名、参数列表必须完全相同 |
| **返回类型** | 无关，可任意修改 | 必须相同或是其子类 |
| **访问修饰符** | 无关，可任意修改 | 不能低于父类（public > protected > default > private） |
| **绑定时期** | 编译时绑定（静态绑定） | 运行时绑定（动态绑定） |

重写遵循"**两同两小一大**"：方法名相同、形参列表相同；子类返回值类型和抛出异常应比父类更小或相等；子类访问权限应比父类更大或相等。返回值是引用类型时，重写可以返回该引用类型的子类。

### 什么是可变长参数？

从 Java 5 开始支持，允许调用方法时传入不定长度的参数。可变参数只能作为函数的最后一个参数，编译后实际被转换成一个数组。**遇到方法重载会优先匹配固定参数的方法**（匹配度更高）。

```java
public static void printVariable(String... args) { ... }
public static void printVariable(String arg1, String arg2) { ... }
printVariable("a", "b");      // 优先匹配固定参数版本，输出 ab
printVariable("a", "b", "c", "d");  // 匹配可变参数版本
```
