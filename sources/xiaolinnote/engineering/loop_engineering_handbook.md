# Loop Engineering 怎么落地？一条从 0 到 1 的上手路径

## 核心答案

**十个开发者，九个到现在都没写过一个能替自己 prompt 的 loop。** 本篇是 loop engineering 的落地手册：先判断「你真需要 loop 吗」，再按「最小四件套」起步，最后守住安全红线。核心结论：**杠杆移走了，你的活也跟着变了，但你别把自己也一起交出去。Build the loop, stay the engineer。**

## 一、先别急，你真需要 loop 吗？

loop 不是白来的：烧 token、花时间搭，真出了岔子还得 debug 一个自己压根没盯着它跑过的系统——**拿真金白银加时间，赌它将来能帮你赚回来**。动手前拿几个问题把自己问一遍：

1. **这活你是不是每周都要干好几遍？** 一锤子买卖，老老实实写个好 prompt 更快更省，搭 loop 纯属杀鸡用牛刀
2. **有没有一个东西能自动告诉你「这活砸了」？**（生死线）测试、类型检查、linter、构建，随便哪个能当裁判都行。没有这个裁判，loop 吐出来的东西还得一行行读 diff 去验——那它到底替你省了啥？
3. **token 预算扛得住浪费吗？** loop 会反复读上下文、重试、试探，不出活也照样烧
4. **agent 能不能跑它自己写的代码？** 得有日志、能复现、崩在哪看得见——要不然它两眼一抹黑，根本没法自我修正
5. **附加题：你到底打算 review 它产出的东西吗？** 不打算？那别建，真的

**一句不讨喜的大实话：loop 是真东西，但大部分人现在还用不上。** 这不是泼冷水，是帮你省下一次「搭了个寂寞」。还有几类活再馋也别碰：**架构、鉴权、支付、生产部署**——一出事就是大事，必须有人盯着。

## 二、第一个 loop 该怎么搭？

新手最容易犯的错：一上来就想搭无所不能的系统（自动化、并行、写查分离、连一堆外部工具一步到位），结果搭到一半被联调问题劝退，或搭出个根本没法 debug 的庞然大物。

**正确姿势：先搭能跑起来的最小版，就四样东西——**

1. **automation（心跳）**：按节奏或事件自动触发。铁律：**停止条件一定要写死**，不然 token 烧光了它还在傻乎乎兜圈子
2. **skill（项目背景）**：用什么框架、有什么约定、踩过哪些坑，写进 skill 文件丢仓库里，agent 每轮自己读
3. **状态文件（命根子）**：记「做完了啥、下一步干啥」，让明天的循环接得上今天。agent 是金鱼记忆，这次会话学的明天一重启就忘干净；**agent 会忘，但 repo 不会**
   - 放哪看你情况：最简单仓库里放一个 `STATE.md`（跟代码一起管、能 diff、谁打开都看得懂，个人/小团队够用）；更正式接外部系统（Linear、GitHub Issues、甚至数据库表——能跨仓库、随时查、团队每个人都看得到 loop 在做什么，正经上生产更适合）
   - 极简 `STATE.md` 长相：

```
# STATE.md
## 进行中
- 升级 lodash 到 4.x，本地测试已过，等 CI
## 今天完成
- 修掉登录接口的空指针，已合并
## 卡住了，等人看
- 支付回调偶发超时，复现不稳定，先挂起
## 下一步
- 扫一遍本周新开的 issue，挑能自动改的
```

   - 还要一个常驻目标文件（`VISION.md` 或 `AGENTS.md`），每轮开工前先读一遍——状态文件记「现在做到哪了」，目标文件管「最终要去哪」；一个盯当下一个盯方向，少了哪个都会跑着跑着忘了自己在干嘛
4. **闸门（裁判）**：测试、类型检查、构建，过不了直接拦下——**loop 唯一能挡住烂活的关卡，千万省不得**

**比凑齐零件更要命的是顺序别搞反**：先让一次手动运行稳稳跑通 → 把背景沉淀成 skill → 包成 loop → 最后才接自动调度。一步稳了再上下一步。手动都没跑顺就急吼吼上调度，回头出了岔子根本分不清是哪一环的锅。**先把路走稳，再谈自动。**

## 三、完整的 loop 还缺哪几块？

最小四件套能转起来但只能干最简单的活。完整 loop 五构件：

| 构件 | 职责 |
|---|---|
| 自动化 | loop 的心跳，按时间或事件触发 |
| worktree | 多 agent 并行各给独立工作区，免得改同一个文件打起来 |
| skill | 项目背景/约定/坑写文件，agent 每轮自己翻 |
| connector | 走 MCP 接 GitHub、Slack、Jira，loop 才能真开 PR、发消息、查告警 |
| sub-agent | 写代码的和验收的拆成两个，别让同一个 agent 给自己打分 |

五样工具里基本都备好了不用自己造轮子（Claude Code：`/loop` + 桌面定时任务 + 云端 Routines；worktree 内置；skill 就是 `SKILL.md`；connector 走 MCP）。

**最该刻进脑子的是 sub-agent「写查分家」**。冷知识：这套玩法听着特别 2026，其实 Anthropic 早在 2024 年底就写进工程博客了，叫 **evaluator-optimizer**——换个新名字又火一遍。道理朴素：让写代码的模型给自己的活打分？准手下留情，跟学生自己批自己卷子一个样。换一个干净上下文、带不同指令的第二个 agent 挑刺，才揪得出第一个自己骗过自己的毛病。**loop 是在你不看的时候跑的，一个你真信得过的验证器，是你敢撒手走开的唯一底气。**

## 四、loop 到底能拿来干嘛？

按从轻到重三档：

**最轻——盯自己手头的活**（一条命令就行，适合所有人）：

```
/loop 10m 检查当前分支 PR 的 CI：有失败就去读日志、修掉、推送；全绿就停下来，给我一句话总结改了什么
/loop 监控这次部署，跑完通知我
/loop 每天早上用 Slack 把我昨天被 @ 的消息汇总一下
```

三段结构：`10m` 心跳 + 每轮要干的活 + 停止条件加交差方式。第二条没写间隔，节奏交给模型自己定。

命令辨析（踩过坑的都懂）：**`/loop` 绑在当前会话上**，关掉终端就停，适合「今天就盯这一件事」的临时轮询；**`/schedule` 把任务丢到云端**，你下班关機它还在跑。`/loop` 陪你白天忙活，`/schedule` 你睡了它接着盯。

**`/loop` vs `/goal`**：普通 `/loop` 按固定节奏重复跑（每隔十分钟一轮，干得对不对它不管）；`/goal` 盯着一个你写好的条件跑（如「所有测试都变绿」），条件不达成就一直跑。且条件达没达成**不是干活的 agent 自己说了算，而是另派一个独立小模型判**——「写的和验的分开」又一次用上，连「我搞定了」都不让动手的 agent 自己下结论。

**中间——每天定时帮你清理**（用上构件，适合有点规模的项目）：最典型「晨间分诊」——每天早上自动跑一轮，读昨天挂掉的 CI、还开着的 issue、最近的提交，判断哪些值得处理写进状态文件，能自己修的修掉提 PR，搞不定的丢进收件箱。等于每天到工位活已分好类。类似还有定时修 CI、依赖升级（定期查新版本，升完跑测试，绿了才提 PR）。见过玩得猛的：一个人挂 loop，一晚上给三十来个开源仓库自动开依赖升级 PR，早上挨个 review。

**最重——让 loop 自己接活、自己验活**（重度玩家）：开源项目有人提 issue，loop 自动读、对照愿景文档判断合不合方向，合就起草 PR，顺手让另一个 agent 先 review 一遍，再交到你面前。从「有人提需求」到「一个审过的 PR 草稿」中间没你什么事。

这一档有个让 loop 越跑越好的技巧：**内外两层循环**——内层 loop 干活，外层 loop 专门吸收你每次 review 时的反馈，改进下一轮怎么干。你每一次「这里改改」都不只修这一次，而是喂给系统让它下回别再犯。**这才是把「设计 loop」的复利真正吃满。**

## 五、你的 loop 是赚是亏？

很多人搭完就傻乐，却没算过账。loop 长期运行持续烧钱，赚亏靠一个指标盯：

> **每个被接受的改动，花了你多少成本。**

把 loop 这阵子烧的 token、占的算力，加上你 review 花的时间，全算进去，除以它真正被你合并了的改动数。配套红线：

> **如果接受率低于 50%，这个 loop 就在亏本。**

产出十个改动看完只有不到五个能用，剩下大半被打回或扔掉——废品消耗的 token 和审查精力已超过帮你省下的活。这种 loop 要么赶紧调，要么干脆关掉。

顺带：sub-agent 按个烧钱，每多挂一个做检查的就多花一份模型和工具的钱。别处处双保险，「再请一个 agent 挑刺」用在真正值得买第二意见的地方就行。**token 宽裕的人和精打细算的人，搭出来的 loop 会很不一样。**

## 六、没人盯着，安全怎么办？

loop 最大卖点是无人值守——反过来念就该警觉：**它在你不看的时候替你干活，也同样在你不看的时候敞着一个没人守的口子**。自动开 PR、自动装 skill、自动连外部工具，每个口子都可能被人钻。四条红线焊死在闸门里，一条都别松：

1. **生成的代码没审就上线**：闸门里光有测试和构建不够，得再塞 SAST（静态安全扫描）、依赖审计、密钥扫描——安全检查和功能检查同待遇，都是上线前必须过的关
2. **skill 本身就是个注入入口**（最阴的一条）：今年 4 月 arXiv 实证研究《Credential Leakage in LLM Agent Skills》——从 skill 平台十几万个 skill 里抽样 **17022 个分析，520 个会泄露凭证，共揪出 1708 处问题**；泄露途径占比最高的不是高深攻击，而是 **debug 日志**（print/console.log 打到标准输出造成 **73.5%** 的泄露），且近九成不需要任何权限就能被利用。skill 是装备齐全的工具箱，agent 能自己翻里面的脚本——反过来，工具箱被人下了毒，agent 照样照单全收（像捡到来路不明的 U 盘直接插公司电脑）。**任何 skill，在 loop 自动装它之前，先把源码从头到尾读一遍**
3. **凭证泄露进日志**：debug 日志是泄露头号途径，生产上跑的 loop 把 verbose 日志关了。开发时打满日志没问题，但别让 24 小时挂跑还连着一堆外部系统的 loop 把密钥哗哗往日志里灌
4. **权限蔓延**（温水煮青蛙典型）：今天加个写权限，明天又加一个，一个月下来它手里的权限大到你自己都说不清它能动哪些东西。解法很笨但管用：**每 30 天把它的权限拉出来复审一遍**，不再需要的收回来

## 七、14 步清单

**第一段 · 先搞清楚要不要做**
1. 想明白本质：你要做的不是 prompt agent，是设计那个替你 prompt 的系统
2. 过一遍四条件：活够重复、验证能自动、token 扛得住浪费、agent 有日志能跑自己写的代码
3. 算清经济账：loop 偏向花得起钱的人，看清自己是受益那类还是该躲那类
4. 对着具体任务跑 30 秒清单：每周至少干一次、有 gate 能拒坏活、agent 跑得了代码、有硬性 stop、不可逆操作前有人把关

**第二段 · 五个构件**
5. 自动化：给 loop 一个按节奏或事件触发的心跳
6. worktree：多 agent 并行各给独立工作区，别让它们改同一个文件
7. skill：把项目背景写成 `SKILL.md`，省得每轮重讲
8. connector：用 MCP 接上 GitHub、Linear、Slack 这些真实工具
9. sub-agent：写代码的和验收的拆成两个，别让它给自己打分

**第三段 · 要么搭对，要么别搭**
10. 加状态文件：让 loop 接着昨天干，而不是每天从零开始
11. 先搭最小可用版：一个自动化、一个 skill、一个状态文件、一道闸门，按「手动跑稳→做成 skill→包成 loop→再调度」的顺序来
12. **防 Ralph Wiggum loop**：用客观的 gate（测试过没过）判断完成，别让 agent 自己喊一声「干完了」就退——这个失败模式是工程师 Geoffrey Huntley 命名的，没有硬 gate，loop 会半途装完工还在那儿空烧钱
13. 还掉理解债：坚持读 diff、抽查闸门、别让 loop 碰架构
14. 交安全税：代码上线前加安全扫描、skill 装前审源、生产关 verbose、权限每 30 天复审

回头看这 14 步：真正难的根本不在中间搭建那段（构件工具早备好了），难的是头一段「要不要做」和尾一段「守不守得住」，**全是关于人的判断**。

> 工具替你跑，但别替你想。——Codez 手册结尾：杠杆移走了，你的活也跟着变了，但你别把自己也一起交出去。**Build the loop, stay the engineer。**
