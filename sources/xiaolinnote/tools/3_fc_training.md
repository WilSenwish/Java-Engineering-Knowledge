# LLM 工具调用面试题 3：大模型的 Function Call 能力是怎么训练出来的？

> **抓取日期**：2026-10-20

> **板块**：LLM 工具调用面试题（22 题）· FC 基础

---

## 核心答案

预训练学不会 FC——语料里没有「给定工具 schema 该输出什么 JSON」的成对样本，模型最多会描述意图不会输出结构化 JSON。两个阶段：**SFT**（完整对话样本模仿学习，反向传播惩罚偏离）+ **RLHF**（人类偏好训练奖励模型，PPO 调整主模型建边界感）。一句话：SFT 教会怎么调，RLHF 教会什么时候调。

## SFT 数据必须覆盖的场景

缺哪个场景就在哪个场景翻车：

1. **单工具调用**（基础款）；
2. **多工具并行调用**（「查北京和上海天气」一次输出两个请求——训练数据没见过就不会并行）；
3. **工具调用失败后的处理**（API 超时/参数错/权限不足，模型要能识别错误换方式，不是崩掉或傻傻重复）；
4. **不需要工具直接回答**（「1+1」「总结这段话」——**如果训练数据全是调用正例，模型会形成「遇到问题就调工具」的惯性，该直接答时也去，画蛇添足**）；
5. **多轮对话中的调用**（上下文已有工具结果，要正确引用而非无视历史重调）。

数据来源：人工标注（质量高，核心种子数据）+ Self-Instruct/Distillation 强模型批量生成（主流，注意幻觉传递要抽查）。

## RLHF 细节

流程：生成多样回答 → 人类标注排序 → 训练奖励模型（RM）→ PPO 强化学习调整主模型。**为什么是 PPO**：① 相对稳定训练不容易崩（传统策略梯度单步更新太大易把模型调废）；② 内置 KL 散度约束，强迫新旧模型输出分布别差太远——防「为讨好 RM 把自己训成只会重复套话的怪胎」。本质是在「追求高奖励」和「保持语言能力」之间走钢丝。

RLAIF：AI 评委代替人类，成本低 10-100 倍，但 AI 偏见会传递（AI 评委觉得「数学题都该调计算器」模型就学到这个倾向）。业界混用：关键数据人工保质量，量大用 AI 提效率。

## 两阶段缺一不可

只有 SFT：遇到什么问题都冲动调工具。只有 RLHF：连 JSON 格式都输出不出，奖励信号没地方发力。
