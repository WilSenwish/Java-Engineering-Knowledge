# LLM 工具调用面试题 18：工具调用格式非法、参数错误、超时或失败时，Agent 如何容错？

## 核心答案

把工具调用拆成**「决策 → 校验 → 执行 → 确认 → 恢复」五阶段**，每阶段不同处理：

- **决策/格式错误**（工具名不存在、JSON 非法、缺字段）：结构化输出 + Schema 拦截，把明确校验错误交模型有界重生成；
- **参数/业务校验失败**（日期范围错、余额不足）：修可确定的格式，缺信息问用户，业务失败重新规划；
- **鉴权失败**：刷新可刷新凭证，越权直接拒绝并审计——**Prompt 代替不了服务端鉴权**；
- **瞬时故障**（连接失败、429、部分 5xx）：满足三条件才重试——可安全重放、总时间预算有余量、次数未超限；指数退避 + 抖动 + 尊重 Retry-After；
- **副作用结果未知**（写请求超时、响应前断连）：调用前生成幂等键写 Checkpoint，超时先按幂等键查状态，确认没执行才重试；查不清暂停任务转人工。

## 故障分类表（先分类再处理）

| 故障类别 | 常见例子 | 推荐动作 |
|---------|---------|---------|
| 模型决策/格式错误 | 工具名不存在、JSON 非法、缺字段 | 结构化校验反馈，模型有界重生成 |
| 参数/业务校验失败 | 日期范围错、订单不存在、余额不足 | 修正格式，缺信息问用户，业务失败重新规划 |
| 鉴权与权限失败 | 凭证失效、用户无权 | 刷新可刷新凭证，越权拒绝并审计 |
| 瞬时基础设施故障 | 连接失败、429、部分 5xx | 安全重放 + 预算允许时有界重试 |
| 明确执行失败 | 下游确认已回滚 | 降级、换工具或结束任务 |
| 副作用结果未知 | 写请求超时、响应前断连 | 幂等键查状态/对账，不盲目重试 |

**HTTP 状态码只提供线索**：连接建立前失败服务端通常没收到；读响应超时服务端可能已执行完。

## 调用前三道门

1. **结构校验**：模型原生结构化输出/受约束解码约束输出 + 宿主按 JSON Schema 校验工具名/类型/必填/枚举/范围；可做无歧义规范化（去空格），不能正则猜收件人金额路径；
2. **业务校验**：`amount` 是数字≠金额可退；`date` 合格式≠会议时间在允许范围——工具适配层查业务状态：资源存在性、版本冲突、前置条件；
3. **权限与风险校验**：宿主依已认证用户身份算权限，服务端最小权限执行；删除/付款/群发进审批。

## 统一错误信封

```yaml
ok: false
call_id: tc_8f21
tool: send_email
error:
  category: rate_limit      # 供策略引擎分类
  code: UPSTREAM_429
  retryable: true           # 当前故障是否可能恢复
  outcome: not_started      # 副作用状态：not_started/failed/succeeded/unknown
  retry_after_ms: 1200
  safe_message: 服务暂时限流  # 模型只收脱敏消息，原始异常留受控日志
```

`retryable: true` 只是条件——工具不能安全重放、任务时限耗尽、用户已取消时都不重试。

## 重试的约束设计

- 瞬时故障进重试候选；每次尝试设超时，整段任务设总 Deadline，**重试前确认退避 + 下次调用不超剩余预算**；
- `Retry-After` 优先遵守，否则有上限指数退避 + 随机抖动（防多实例同时重击下游）；
- **重试放一个层级**：SDK/适配层/调度层各重试三次会成倍放大——让最了解幂等性和任务预算的一层负责，其他层关闭或纳入同一预算；
- 取消向下传播：调度器取消未开始的调用，通知执行中的工具停止可中断工作；工具实现要检查取消信号释放连接/线程/临时文件。

## 熔断、降级、故障转移

- **熔断**：连续失败/错误率达配置 → Open 快速失败 → 冷却后 Half-Open 探测 → 成功回 Closed；
- **降级**：返回缓存数据/只读模式/语义等价备用服务；**降级结果要告诉模型数据是否陈旧、缺哪些字段**，防模型把残缺结果包装成完整答案；
- **故障转移边界**：两个搜索服务可互替（统一结果协议）；两个付款渠道不共享交易状态和幂等范围，贸然切换可能两笔扣款——备用工具须满足相同权限、一致性、副作用约束。

## 幂等键与 Checkpoint

- 幂等键首次执行前生成（`run_id + step_id`），重试/重启/人工恢复都复用同一键；
- 服务端持久化「键 + 参数摘要 + 状态 + 结果」；同键同参返回已有结果，**同键不同参拒绝**；
- 业务写入与幂等记录同事务边界，或用事务消息/Outbox/对账补偿收敛；
- **exactly-once 有边界**：下游不支持去重、记录过期、跨多系统一次调用都可能部分成功——工程目标是「至少一次到达 + 幂等/去重/查状态/补偿让业务效果在约定范围只发生一次」；
- Checkpoint：副作用前写（步骤/工具/参数摘要/幂等键/pending），确定结果后更新 succeeded/failed；重启后 pending/unknown 先查下游；**推理节点与副作用执行节点分开**，避免恢复时模型重新生成一次付款动作；
- 查不清暂停运行保存现场转人工；高风险操作首次执行前主动暂停让用户确认。

## 监控与审计

一次 Trace 串 `run_id`/`step_id`/`tool_call_id`：工具及 Schema 版本、模型与 Prompt 版本、参数脱敏摘要、调用方身份、起止时间、每次尝试、错误类别、重试/降级决策、Checkpoint 状态、最终结果。

指标：各工具成功率、延迟分位数、重试率、熔断状态、unknown 结果数、幂等去重次数、人工接管量；审计记谁批准了高风险动作、批准了哪些参数。**完整调用链才能回答三问：失败在哪层、为什么重试或停止、副作用最终有没有发生**。
