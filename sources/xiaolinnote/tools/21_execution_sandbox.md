# LLM 工具调用面试题 21：Agent 的代码执行沙箱应该如何设计？

## 核心答案

**让代码只拿到当前任务需要的权限，把资源消耗限制在预算里**。模型生成的代码按不可信代码处理：不能只靠 Prompt 约束（操作系统看进程身份和权限，不读 Prompt），不应直接继承宿主全部权限。

- **访问边界**：只提供本次任务输入（只读），临时目录和输出目录可写，低权限身份运行；网络按需开放；宿主凭据和管理接口不交给代码；
- **资源预算**：CPU、内存、进程数、运行时间，**作用于整个任务进程集合**（不只启动的那个进程）；
- 容器可作为实现但要查挂载/权限/网络配置——普通 Linux 容器共享宿主内核；任意用户代码评估虚拟机；
- **沙箱外运行器**管理全生命周期：准备输入 → 启动受限执行 → 超时/取消终止整个执行单元 → 核对导出允许产物 → 清理环境。

## 为什么限制运行环境而不是只检查代码

程序真正能做什么取决于运行时拥有的能力。OS 处理文件读取/网络连接/进程创建时检查进程身份、访问权限和系统规则——不会因为代码来自「数据分析任务」就自动只允许分析数据。Prompt 影响模型怎么生成代码，代码审查能发现问题，**都不能代替运行时限制**：一次真实访问发生时，必须有执行环境能拒绝超范围操作。

边界含两方面且不能互替：**访问限制**（能接触什么）+ **资源限制**（能消耗多少）。看不到宿主文件仍可能占满内存；只跑几秒也可能读走敏感数据。

## 访问边界：按任务分配最小能力

- **文件**：每任务独立空间——只读输入/可写临时区/输出区；依赖预置，代码不改原始数据；
- **工作目录 ≠ 文件边界**：只决定相对路径起点，程序仍可访问绝对路径或父目录；真正限制要文件系统视图 + 访问权限配合（namespace 提供独立挂载视图，但**挂进去的内容仍按实际权限处理**——可写挂载用户目录 = 沙箱获得这些文件访问能力）；
- **网络**：独立网络环境只解决视图和连接环境，不等于限制出站目标；不需要联网不给外部访问；需要时用网络策略/受控接口限制；
- **文件只读防不住数据外传**：能读内容 + 任意网络 = 可把内容发出去——文件和网络权限一起考虑；
- **凭据不无差别继承**：宿主环境变量的数据库密码/云密钥/管理接口不因启动子进程进代码环境；必须的外部能力由沙箱外工具代理，受限身份执行，返回必要结果。

权限在任务开始前明确分配——外部材料或生成代码即使写「需要更多权限」也不会自行改变执行环境配置。

## 资源限制：对象是整项任务

主程序创建后台进程后自己退出，只统计/停止主程序，后台进程继续占机器——**要把它们归入同一受控执行单元一起计量、限制和终止**（Linux cgroup 按组管理 CPU/内存/任务数）。

| 限制对象 | 约束什么 |
|---------|---------|
| CPU 配额 | 一段时间内计算资源占用 |
| 内存 | 任务可用内存规模 |
| 进程与线程数 | 不断创建执行单元的行为 |
| 总运行时间 | 等待或执行持续过久 |
| 文件与输出大小 | 临时数据/产物/日志无界增长 |

- **CPU 配额 ≠ 总时长**：等外部响应几乎不用 CPU 却可能一直不退；持续计算跑很短时间也可能挤占别人；
- 内存可能在超时前迅速增长；磁盘空间需配额或其他存储控制，日志接收要上限——防沙箱没耗尽资源、运行器先被大量输出拖垮；
- 额度按任务需要定；限制触发记录原因，让调用方分辨程序错误还是预算不足。

## 容器够不够用

普通 Linux 容器独立文件/进程/网络视图 + 权限资源机制，轻量好部署，可作为基础实现。但**容器进程最终用宿主内核**——视图分开不代表底层两套 OS。两类问题：

1. **配置把能力交还**：敏感挂载、特权模式、能管理容器的高权限控制接口给代码——程序可能借这些入口影响宿主；
2. **共享内核**：配置合理也与宿主内核交互，内核和隔离实现的漏洞纳入风险判断。

对策：低权限身份运行、移除不需要的特权能力、限制不必要的系统调用（减少代码能直接请求的内核操作）——但不追求连正常依赖都跑不了的配置，按任务验证必要能力。

**任意用户提交代码或需更强任务间隔离 → 评估虚拟机**（独立客体内核，代码先与客体内核交互再经虚拟化层连宿主）；更强边界有启动/资源/运维成本，且仍要正确配置——把宿主敏感文件共享给 VM 仍是授权访问。

## 沙箱外运行器：全生命周期管理

运行器处于生成代码不能修改的管理边界外（否则代码能改自己的限制和回收逻辑）：

1. **启动前**：分配任务空间、放入允许输入、应用权限资源配置；**配置失败不退回到不受限宿主执行**（防「为了跑起来」绕过边界）；
2. **执行中**：跟踪状态与预算，处理超时和取消；终止覆盖整个执行单元并确认相关进程结束——不能只停止接收输出让后台任务继续跑；
3. **结束后**：产物不立即获宿主权限——**核对实际对象**（输出目录里的符号链接指向目录外文件：只查路径文字以 output 开头不够，仍可能导出不该读的内容）；只导出允许范围文件，限制类型/大小/数量；批处理先停执行单元再检查复制产物；
4. **清理**：清临时数据、撤临时访问能力、保留受控诊断记录；
5. **任务间隔离**：复用基础环境省启动开销，但不继承上一任务数据/后台进程/凭据；没确认清理成功不交给下一位用户。

**沙箱验证操作是否在能力和资源边界内，不证明计算结果正确**——文件生成成功只说明产物存在，内容是否满足任务要求靠业务规则或测试另外验证。隔离与结果验证分别落实。
