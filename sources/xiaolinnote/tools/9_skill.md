# LLM 工具调用面试题 9：什么是 Skill（技能）？和 Tool、Prompt 有什么区别？

## 核心答案

**Skill 是一个可复用的「能力包」**——把指令、脚本、模板、参考资料打包成一个文件夹，里面有一个 `SKILL.md` 作为入口。Agent 启动时扫描 Skill 目录，自动发现有哪些技能可用；遇到匹配任务时**按需加载**对应 Skill，按其指令执行。

一句话定位：**Skill = 教 Agent 做某类事的操作手册 + 配套工具箱**。

## Skill 的组成结构

```
my-skill/
├── SKILL.md          # 入口：name + description + 指令正文
├── scripts/          # 可选：可执行脚本（Python/Shell）
├── references/       # 可选：参考资料、API 文档
└── assets/           # 可选：模板、静态资源
```

- `SKILL.md` 头部必须有 `name` 和 `description`——这是 Agent 判断「这个技能何时该用」的**唯一依据**；
- 正文是流程指令（第一步做什么、第二步做什么、遇到 X 怎么办）；
- 脚本和参考资料按需取用，不是每次全量加载。

## 渐进式加载：三层机制

Skill 解决的核心矛盾是「能力很多 vs 上下文很贵」：

| 层级 | 加载时机 | 加载内容 | Token 成本 |
|------|---------|---------|-----------|
| **第一层：发现** | Agent 启动时 | 仅 name + description | 每个约 30-50 token |
| **第二层：激活** | 任务匹配某 Skill 时 | SKILL.md 指令正文 | 几百到几千 token |
| **第三层：执行** | 指令中提到具体资源时 | 脚本/参考资料/模板 | 按需 |

设计精髓：**启动时成百上千个 Skill 也只花几千 token 刷个「目录」，只有相关的才展开细读**——和 MCP 工具列表按需暴露是同一思想。

## 发展历史

- **2025-10**：Anthropic 在 Claude 中推出 Agent Skills；
- **2025-12**：开源为开放标准（Agent Skills 规范），任何 Agent 框架可接入；
- 此后成为「给 Agent 沉淀领域方法论」的主流形态。

## Skill vs Tool vs Prompt vs Slash Command

| 维度 | Tool | Prompt | Skill | Slash Command |
|------|------|--------|-------|---------------|
| 本质 | 可调用的函数 | 一次性指令 | 能力包（指令+资源+脚本） | 用户手动触发的快捷指令 |
| 粒度 | 单次原子操作 | 单条消息 | 完整工作流 | 单条消息 |
| 触发方 | 模型自主决定 | 开发者写死 | Agent 自动匹配 | 用户输入 `/xxx` |
| 复用性 | 跨会话 | 不复用 | 跨会话跨项目 | 跨会话 |
| 类比 | 厨房电器 | 口头吩咐 | 菜谱+电器清单 | 菜单上的固定套餐键 |

**关系**：Skill 内部通常会调用多个 Tool；Skill 描述的是「做一类事的完整方法」，Tool 是「单个动作」。
