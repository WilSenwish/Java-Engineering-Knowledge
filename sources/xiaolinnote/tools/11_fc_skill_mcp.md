# LLM 工具调用面试题 11：Function Calling、MCP、Skill 三者是什么关系？

## 核心答案

三者构成 LLM 工具调用的**三层架构**：

> **FC 是语言、MCP 是工具箱、Skill 是操作手册。**

| 层 | 组件 | 解决的问题 | 抽象层级 |
|----|------|-----------|---------|
| 语言层 | Function Calling | 模型如何表达「我要调工具」的意图 | 单次调用消息格式 |
| 工具箱层 | MCP | 工具如何标准化封装、发现、复用 | 生态协议 |
| 操作手册层 | Skill | 某类任务的正确流程是什么 | 工作流知识 |

## 依赖链：Skill → MCP → FC

三者自底向上依赖：

1. **FC（最底层）**：没有 FC，模型连「调用工具」这句话都不会说——所有上层都无从谈起；
2. **MCP（中间层）**：MCP Server 提供的工具最终要通过 FC 暴露给模型（`list_tools` → 转 FC 格式）；
3. **Skill（最上层）**：Skill 的流程指令里调用的正是 MCP 工具——手册说「用 git 拉代码」，手（MCP）去执行。

## 做菜类比

| 概念 | 类比 | 说明 |
|------|------|------|
| FC | **手** | 用手抓锅、拧火，是基本动作能力 |
| MCP | **厨房** | 锅碗瓢盆、食材调料整齐摆放，伸手就能拿到 |
| Skill | **菜谱** | 先热锅、再下油、七分热下料——做一道菜的完整方法 |

只有手没有厨房，每样东西现找；只有厨房没有菜谱，面对满架食材不知道先动哪个；只有菜谱没有厨房，菜谱落不了地。**三层齐备才能稳定产出**。

## 完整场景串联：数据分析

用户说「帮我分析上季度销售数据并生成报告」：

```
【Skill 层】data-analysis Skill 激活
  指令：① 取数 → ② 清洗 → ③ 统计 → ④ 可视化 → ⑤ 生成报告

【MCP 层】按指令逐个调用工具
  - db.query 执行 SQL 取销售明细          （工具：数据库）
  - python.run 执行 pandas 清洗统计        （工具：代码执行）
  - file.write 保存图表和报告               （工具：文件系统）

【FC 层】每次调用都是一次结构化 JSON
  {"name": "db.query", "arguments": {"sql": "SELECT ..."}}

宿主代码执行工具 → 结果喂回 → 模型继续下一步（FC 两轮对话闭环）
```

**分层次答面试题**：被问 FC 答「模型输出结构化 JSON 的调用语言」；被问 MCP 答「工具生态协议，M+N 变 M+N」；被问 Skill 答「流程知识包，渐进式加载」；被问三者关系答「语言+工具箱+操作手册的三层架构」。
