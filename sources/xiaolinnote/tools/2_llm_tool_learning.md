## 核心答案

训练两个阶段：**SFT 教会「怎么调」，RLHF 教会「什么时候调」**。原始 LLM 预训练只学「预测下一个 token」，从没见过工具调用——prompt 里写「你可以调用天气 API」它也只生成「我需要调用天气 API」的自然语言描述，不会输出可解析 JSON。**工具调用能力不是涌现出来的，是后天专项训练教出来的**。

## SFT：让模型「见过」工具调用

一条完整训练样本 = system（工具定义说明书）+ user（提问）+ **assistant（结构化 JSON 调用请求，这是「正确答案」）**+ tool（模拟返回）+ assistant（最终自然语言答案）。几十万到上百万条样本反复训练，模型学会「识别工具定义→判断要不要调→输出规范 JSON」整套流程。

数据来源：人工标注（质量高成本高，用于核心种子数据）+ 强模型批量生成再人工抽查（业界主流，注意「蒸馏幻觉传递」——上游模型错样本会被下游学进去，抽查不能省）。

## RLHF：建立「该不该调」的边界感

SFT 短板：训练样本里「该调」占绝大多数，模型过拟合「积极调用」倾向——问「1+1 等于几」也去调计算器。四步：① 同一问题生成多样回答（调工具的/直接答的/参数错的）；② 人类标注排序（「1+1」直接答排第一，调工具画蛇添足排末尾）；③ 训练奖励模型（RM，专门打分的「裁判」——**人类判断被蒸馏进裁判，标注员水平不稳定 RM 就学到歪标准**）；④ PPO 等强化学习调主模型参数趋向高分回答。

RLAIF 变体：用更强 AI 代替人类打分，成本低 10-100 倍速度快，但「AI 的偏见会传递」。

## 运行时：Function Calling

应用把工具 schema + 问题发给模型 → 模型输出结构化 JSON 调用请求（**模型到这里就停了，不执行**）→ 代码解析执行 → 结果塞回对话 → 模型组织自然语言回答。**模型只负责决策（理解意图和推理），宿主程序负责执行（权限控制/参数校验/沙箱）**——这个分工让工具调用既灵活又安全。
