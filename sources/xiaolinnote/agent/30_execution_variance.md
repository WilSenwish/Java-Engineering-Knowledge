# Agent 面试题 30：相同输入为什么会得到不同的 Agent 执行结果？

## 核心答案

「相同输入」先分三层：**用户文本相同**（历史/指令/记忆/任务进度可能已不同）、**模型请求相同**（装配材料和参数一致）、**执行环境相同**（模型版本/工具环境/初始状态一致）。差异来源五类：请求内容、采样、数值计算、工具观察、并发调度。排查靠运行轨迹对齐找**最早可观察分歧**，分层回放验证。稳定性分层定义：措辞和路径可以不同，事实、计算、权限约束、写操作去重必须一致。

## 三层比较范围

| 层次 | 需固定 | 仍可能变 |
|------|--------|---------|
| 用户文本 | 当前这句话 | 历史、指令、记忆、任务进度 |
| 模型请求 | 实际提交的完整材料与参数 | 模型实现、外部工具观察 |
| 执行环境 | 相关模型版本、工具环境、初始状态 | 采样、计算、调度中未控因素 |

完整运行条件不只是启动快照——任务读当前时间、调实时接口，执行中新增输入也要算。

## 模型层：采样与数值

自回归模型每步算候选分数，生成策略决定选哪个（45%/40%/15% 分布采样，高分候选不保证每次选中）。选中不同候选，后续生成条件就变了——最初只是措辞，可能逐渐改变工具名称、参数或计划。

**temperature=0 vs 固定 seed 各控一段**：

- temperature=0（贪心）消除显式采样变化，但**最高分是谁要经过实际数值计算**——有限精度舍入、并行累加顺序、批处理/内核差异，数学等价的计算不一定逐位相同；候选分数接近时，小误差就改变排序；
- seed 控伪随机过程（同算法同初始状态同调用顺序 → 同序列），但候选分布变了同一序列选出不同候选；随机数使用顺序变了同 seed 也不保证每步一致；
- 都不能固定模型权重、工具数据、应用状态。模型版本别名 ≠ 固定权重和推理实现。

## 系统层：工具观察与并发

- 工具读当前环境不是固定答案：数据库会更新、文件会被改、索引会重建；
- **顺序也是差异源**：无排序的查询不能依赖返回顺序；按某字段排序但字段有重复值仍需稳定依据（取第一项的业务要加唯一编号）；
- **并发返回顺序**：两个工具谁先返回取决于实际耗时，按到达顺序入上下文 → 两次模型输入排列不同。需固定顺序就等结果齐了按任务编号组织；有依赖直接约束执行顺序；
- 共享状态并发覆盖：两进程基于同旧版本改进度，后返回覆盖新状态——调采样参数没用，靠独立任务状态/受控更新顺序/版本条件检查。

## 多步闭环放大差异

```text
本轮上下文 → 模型选动作 → 工具产生观察 → 更新任务状态 → 新上下文 → …
```

一轮输出经两条路影响后续：留在历史里 + 通过工具改变外部环境再被读回。**第一轮一点不同，第二轮就面对不同材料**；超时/重试/压缩/预算限制会继续放大分歧（某路径多走几步更早触发压缩 → 保留材料不同 → 影响新判断）。固定第一轮 seed 保证不了整条任务一致。但局部差异不一定持续放大——两路径可能最后读到相同事实，是否影响结果取决于任务的分支、依赖和验证。

## 排查：最早可观察分歧

记录每轮实际提交的上下文、模型与生成配置、模型返回、工具参数和真实结果、状态更新与执行顺序，按任务/步骤/调用编号关联成轨迹。沿数据流向前找：请求已不同？输出不同？工具返回不同？相同事件下程序更新出不同状态？

| 最早分歧点 | 优先核查 |
|-----------|---------|
| 调模型前的请求 | 指令版本/历史/记忆/整理/消息顺序 |
| 相同请求的模型输出 | 生成配置/具体模型版本/推理环境 |
| 相同动作的工具返回 | 数据版本/调用身份/时间/工具实现 |
| 相同结果的状态更新 | 并发/重试/取消/恢复/状态处理代码 |

分支不同后不能机械比两边「第七步」——先比共同前缀，再按动作和依赖分析分叉。请求内容指纹快速判断材料变化，但解释差异还要能还原原内容。

## 分层回放

| 方式 | 重跑哪些 | 验证什么 |
|------|---------|---------|
| 事件回放 | 只重跑解析/调度/状态处理程序 | 已知事件是否被正确处理 |
| 固定观察后重跑 | 模型用保存的观察/模拟环境反馈 | 固定材料下生成行为怎么变 |
| 环境恢复整体重跑 | 模型+工具+运行程序全重跑 | 整条任务能否重复完成 |

回放要控制代码读的其他输入（当前时间/随机数/事件顺序）。模型提出记录里没有的新工具请求 → 不能拿另一次查询结果冒充，要模拟环境支持或停止说明。副作用（发通知/建记录）要隔离或模拟——**模拟回放的成功只能作为测试证据，不能写成线上已执行成功**。

## 稳定性分层定义

| 层次 | 要求 | 例子 |
|------|------|------|
| 表达 | 可不同 | 措辞不同但同一事实 |
| 过程 | 看任务约束 | 审核流程必须先批后执行；资料汇总允许检索顺序交换 |
| 结果 | 必须一致 | 两次算出不同金额 = 有问题 |
| 约束 | 必须满足 | 权限检查、写操作去重（稳定操作标识+后端去重） |

**明确计算用确定规则和工具，资源访问落实权限检查，业务写入用稳定操作标识**。模型在允许范围内选路线，关键条件由程序核验。外部事实变化时正确行为也该变——为输出永远相同强行忽略新数据会损害正确性；复现用于研究已发生过程，实际执行仍依据当前有效事实。
