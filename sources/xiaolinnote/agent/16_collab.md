## 核心答案

协作两种基础模型：**消息传递**（Agent 之间发消息，解耦、可扩展）与**共享状态**（LangGraph State，Agent 读写同一份状态，直接、可控）。任务切换两种路由：**静态路由**（代码写死流转规则，可预测）与**动态路由**（LLM 决定下一步，灵活但多一次调用、可预测性下降）。**Handoff 模式**（OpenAI Swarm 为代表）是动态切换的教育性实现。

## 通信：消息传递 vs 共享状态

| 维度 | 消息传递 | 共享状态（LangGraph State） |
|------|---------|---------------------------|
| 耦合 | 低，只需约定消息格式 | 高，共用一个 State schema |
| 可观测 | 消息可持久化、可审计 | 状态变更集中可见 |
| 扩展 | 加 Agent 不动其他人 | 改 schema 影响所有节点 |
| 调试 | 追消息流 | 追状态 diff |

## 路由：静态 vs 动态

- **静态路由**：A 完成后一定去 B。可测试、可预测、成本低；
- **动态路由**：LLM 读当前状态决定下一个 Agent。灵活，但每次多一次 LLM 调用，且路由决策可能不稳定；
- **混合策略（推荐）**：主流程用静态路由保底，边缘分支用动态路由兜异常——既稳又灵。

## Handoff 模式

一个 Agent 直接把对话控制权移交给另一个（带上下文交接）。要点：

- 移交时传什么：任务描述、已完成上下文、可用工具列表；
- **防循环**：必须设移交次数上限/已访问集合，否则 A→B→A 无限转；
- Swarm 定位是教育性框架，生产常用 LangGraph 的图结构表达同样语义。

## 与容错的衔接

通信可靠性（丢消息、重复、乱序）与协作正确性（语义冲突、重复劳动）是两层问题，治理手段见题 22（Multi-Agent 容错）。
