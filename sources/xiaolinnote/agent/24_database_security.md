# Agent 面试题 24：Agent 直接操作数据库有什么安全问题？怎么保证租户隔离？

## 核心答案

**模型不是数据库防火墙**——Agent 生成 SQL 直接执行，等于把用户输入直接送进数据库。三道防线：最小权限、租户隔离（策略层注入/查询构造器/数据库行级策略三层）、SQL 校验看 AST 不只看开头。写操作必须「准备→审批→提交」两阶段。

## 最小权限

Agent 用独立数据库账号，只授必要的表级权限；生产库只读，写走审批通道。绝不給 DDL/全库权限。

## 租户隔离三层

1. **策略层注入**：按当前租户上下文强制追加 `WHERE tenant_id = ?`，从源头限域；
2. **查询构造器**：用参数化 ORM 方法而非字符串拼接 SQL，杜绝注入；
3. **数据库行级策略（RLS）**：最后兜底，数据库本身按策略过滤行。

三层是纵深防御，任何单层失守其他层还能兜住。

## SQL 校验

- 只看「开头是不是 SELECT」不够——`SELECT ...; DROP TABLE ...` 或子查询里的写操作；
- 正确做法：解析成 **AST 做 Allowlist 校验**（只允许 SELECT、只允许白名单表/列、禁止多语句）；
- **Text-to-SQL 受控化**：schema 裁剪 + few-shot + 语法预检，不让模型自由发挥。

## 两类特有风险

- **数据库文本即提示词注入面**：表里存的内容可能带「忽略之前指令」——读取的数据要当不可信输入处理；
- **查询幻觉（口径问题）**：模型把「本月活跃用户」按自己的理解写错口径。需要口径字典/语义层固化指标定义。

## 写操作两阶段

「准备 → 审批 → 提交」：先 dry-run 出将执行的 SQL 和影响行数，人审或策略审通过后才真正提交。
