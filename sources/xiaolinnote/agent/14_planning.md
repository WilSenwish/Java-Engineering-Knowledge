## 核心答案

规划能力主流是三层演进：**CoT（思维链）**单链推理 → **ToT（思维树）**多分支搜索 → **GoT（思维图）**图结构复用。成本逐级上升（ToT 约 3~5 倍，极端 10 倍+）。工程上最常用的是 **Plan-and-Execute + Re-planner**，与 ReAct 搭配：先出计划，再逐步执行，失败时重规划。

## CoT / ToT / GoT 对比

| 维度 | CoT | ToT | GoT |
|------|-----|-----|-----|
| 结构 | 单链，一步步往下推 | 树，每步生成多个候选分支 | 图，节点可被多条路径复用 |
| 纠偏能力 | 无，错了将错就错 | 有，评估-剪枝，坏分支淘汰 | 有，且中间结果可合并 |
| 搜索 | 一次到底 | 生成→评估→剪枝的循环 | 图上聚合与归纳 |
| 成本 | 1x | 3~5 倍 | 更高，尚处学术阶段 |
| 适用 | 简单推理、日常问答 | 多路径探索（数独、创意方案） | 复杂依赖的组合推理 |

## 工程主流：Plan-and-Execute + Re-plan

1. **先规划**：把复杂任务拆成有序子任务列表（可结合题 7 的任务拆分方法论）；
2. **再执行**：逐个执行，每步结果回写计划状态；
3. **失败重规划**：某步失败或环境变化时，Re-planner 基于已完成部分重新生成剩余计划，而不是从头再来；
4. **与 ReAct 搭配**：每个子任务内部用 ReAct 循环（思考-行动-观察），整体用 Plan 骨架。

## 面试要点

- 不要神化 ToT/GoT：生产里纯 ToT 成本高且慢，只在少数高价值场景用；
- 规划能力的本质是**把「一次生成」变成「生成-验证-修正」的闭环**；
- Re-plan 的存在说明规划必须容忍环境不确定性——计划不是契约，是假设。
