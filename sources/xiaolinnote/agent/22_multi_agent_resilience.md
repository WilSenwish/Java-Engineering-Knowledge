# Agent 面试题 22：Multi-Agent 系统有哪些容错机制？一个 Agent 挂了怎么办？

## 核心答案

先分层看故障：**通信问题**（消息丢、重、乱、心跳停）和**一致性问题**（两个 Agent 改同一文件、同一任务被干两遍、语义冲突）要用不同手段治。核心机制：心跳+租约、checkpoint+幂等接管、任务/文件所有权、worktree+乐观并发、唯一 Integrator 最终提交权。

## 通信层容错

- **心跳 + 租约**：Agent 定期上报心跳；租约到期未续约即判定失联，触发接管；
- **generation fencing token**：失联 Agent 恢复后，旧代际的写入直接拒绝——防止「僵尸 Agent」复活后覆盖新主的数据；
- **checkpoint + 幂等接管**：任务状态定期存档，接管方先核对未决操作（哪些做了一半），用幂等键保证重复执行不出双份结果。

## 一致性层容错

- **任务/文件所有权**：开工前先「认领」，从根上减少重叠劳动；
- **worktree + 乐观并发**：各自在隔离工作区干活，合并时乐观并发控制；热点文件加短锁；
- **唯一 Integrator 最终提交权**：只有一个集成者有权做最终合并提交，杜绝多头合并；
- **语义冲突 Git 发现不了**：文本能合 ≠ 语义对（A 把函数删了、B 改了函数体）。合并前必须跑验证（编译+测试）而不是只看 diff 无冲突。

## 面试金句

- Multi-Agent 的故障不是「一个挂了」这么简单，是**挂了之后它还诈尸**（fencing token 要解决的就是这个）；
- 通信层保「消息可靠」，一致性层保「结果正确」，两层治理不能互相替代。
