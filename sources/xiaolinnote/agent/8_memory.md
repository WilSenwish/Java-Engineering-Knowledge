## 核心答案

记忆机制分四层：**感知记忆**（当前输入原始内容）、**短期记忆**（context window 对话历史）、**长期记忆**（外部数据库、语义检索召回）、**实体记忆**（结构化提取的关键事实）。

设计记忆模块解决三个核心问题：**存什么、怎么存、什么时候取出来用**。

## 为什么需要记忆

今天告诉 Agent「我喜欢代码风格简洁、变量命名用英文、不要过度注释」，明天新对话它输出中文注释一堆——昨天的对话对它压根不存在。更严重的是任务状态问题：多步任务没有短期记忆，就不知道上一步做了什么、当前哪个阶段、收集了哪些信息。「先查资料再整理报告」，没有记忆的话整理这一步根本不知道查到了什么。**记忆是 Agent 从「单次问答工具」变成「真正助手」的关键分水岭。**

## 四种记忆类型（从最短暂到最持久）

借用认知科学词汇建立直觉（工程实现通常是向量检索 + metadata 过滤，不一定真分这么细）：

| 类型 | 载体 | 容量 | 生命周期 | 访问方式 |
|------|------|------|----------|----------|
| **感知记忆** | 当次输入 | 极小 | 单次调用 | 即时访问 |
| **短期记忆** | context window（messages） | 受 token 限制 | 一次任务 | 直接读取 |
| **长期记忆** | 向量/关系数据库 | 无限 | 持久 | 语义检索 |
| **实体记忆** | 结构化存储 | 无限 | 持久 | 精确查询 |

1. **感知记忆（Sensory Memory）**：当前这次调用的原始输入（用户消息、截图、文档）。生命周期只有一次调用，处理完就消失。
2. **短期记忆（Short-term Memory）**：context window 里的 messages 列表，维持当前任务完整状态（用户说了什么、模型输出什么、工具返回什么）。像「工作台」——桌上摆着正在处理的东西，有大小限制（token 上限），放满要清理；随时可见不需要「翻箱倒柜」。
3. **长期记忆（Long-term Memory）**：跨任务保留，存外部数据库（向量库/关系库/KV）。像「档案室」——东西放进去不丢，但用的时候要主动翻。关键技术是向量数据库的**语义检索**：不需要知道存时用的什么关键词，意思相近就能检索到（存「用户不喜欢冗长的注释」，用「代码风格偏好」也能查到）。三个子类型：
   - **情节记忆（Episodic）**：具体事件经历（「上周二用户让我写爬虫，遇反爬，最后用 Selenium 解决」）——新任务时检索相似经历，参考上次怎么解决的，避免重复踩坑；
   - **语义记忆（Semantic）**：从多次经历提炼的通用规律（「目标网站有 JS 动态渲染时 requests 抓不到，应优先 Selenium/Playwright」）——信息密度更高，检索更易命中；
   - **程序记忆（Procedural）**：怎么做某件事的操作流程/SOP（「部署 Flask 标准步骤」）——重复性任务直接调出执行，快且稳。
4. **实体记忆（Entity Memory）**：比长期记忆更精炼——**不是存原文，而是把对话中关键实体和事实主动提取成结构化字段**（「用户偏好 Python」「客户预算 5 万」「项目截止日 3 月底」）。类比医生病历卡：不存问诊录音，结构化记录「主诉/诊断/用药」。信息密度高、查询快、不受原始表述影响。

## 三个核心工程问题

**① 存什么？** 不是所有内容都值得写入长期记忆——存太多引入噪音、检索精准度下降。判断标准：**「这条信息，下次任务开始时如果知道，会让 Agent 做得更好吗？」**

- 值得存：用户偏好和习惯（语言风格、技术栈偏好）、任务执行中的关键结论和决策（「竞品 A 定价按用量收费」）、外部知识（产品文档、FAQ、历史案例）；
- 不值得存：中间推理过程、工具返回的原始数据（日志太啰嗦）、闲聊内容——存进去只稀释有价值记忆。

**② 怎么存？** 按信息类型选存储介质，不一刀切全塞向量库：
- 需要语义检索的非结构化文本（文档知识、对话摘要）→ 向量数据库；
- 结构化偏好和状态字段（语言偏好、项目配置）→ 关系数据库或 KV 存储（精确查询快）；
- **混合存储是主流做法**：结构化字段用关系库精确查，非结构化知识用向量库语义检索。

**③ 什么时候取？** 两种策略结合使用：
- **主动检索**：任务开始前，用任务描述检索相关记忆，注入 system prompt 作为背景知识——Agent 一开始就带着「历史记忆」，用户不用每次重新交代背景；
- **被动触发**：Agent 推理过程中判断当前步骤需要某类知识时，主动发起检索——把「查记忆」封装成一个 Tool，让 Agent 自己决定什么时候调。更灵活但依赖模型判断。
- **实践：session 开始时做一次主动检索（用户偏好和背景加载进 system prompt），执行中按需检索特定知识。**

## Context Window 管理（短期记忆工作台不够大）

1. **滑动窗口**：只保留最近 N 轮，更早丢弃。简单但可能丢早期重要信息（用户第一轮说「所有代码用 TypeScript」，第十轮被滑出窗口后 Agent 又开始写 JavaScript）；
2. **摘要压缩**：历史接近上限时用 LLM 把早期对话压缩成摘要替换原始历史（「用户要求用 TypeScript 编写 REST API，已完成数据库设计和路由定义，当前实现用户认证模块」——token 从几千降到几百）。代价：压缩丢细节 + 额外 LLM 调用；
3. **卸载到长期记忆**：中间结果当前步骤不需要但后面可能用 → 先存向量库、从 context 移除，需要时检索回来。给工作台配「抽屉」。

**开源记忆框架**：
- **Mem0**（GitHub 5w+ 星）：记忆管理做成独立服务层，`memory.add()` / `memory.search()`，底层 embedding、去重、冲突消解全包。适合个性化记忆，按 user_id 隔离，同时支持向量存储和图存储；
- **Letta（前身 MemGPT）**：灵感来自操作系统内存管理。三层：**Core Memory**（始终留在 context 的核心信息：用户画像、当前任务目标）/ **Recall Memory**（最近对话历史，按时间存储）/ **Archival Memory**（长期归档知识）。**最有意思：让 Agent 自己通过工具调用管理三层记忆**（自己决定什么时候把信息从 Core 移到 Archival）；
- **Zep（开源组件 Graphiti）**：引入「时间感知」——给每条记忆标注有效时间窗口（「用户预算 5 万」可能三个月后过期），用时序知识图谱管理记忆生命周期，自动识别过时/有效记忆。

## 知识图谱：让记忆之间产生关联

向量检索本质是「一条一条」存取，记忆之间独立无关联。但信息之间的关系和信息本身一样重要：存了「用户 A 是公司 B 的 CTO」和「公司 B 主营云计算」，纯向量检索答不了「用户 A 所在公司做什么业务」（两条文本相似度不高）。

**三元组结构**（实体 → 关系 → 实体）：「用户 A → 担任 CTO → 公司 B」「公司 B → 主营业务 → 云计算」「公司 B → 成立于 → 2015 年」。查询沿关系链**多跳推理**：从「用户 A」沿「担任 CTO」找到「公司 B」，再沿「主营业务」找到「云计算」，两跳拿到答案——这是向量检索做不到的。

**配合方式**：向量库处理模糊语义检索（「之前那个项目」），图谱处理精确关系推理；对话中用 LLM 自动提取实体关系入图谱；检索时向量检索拿候选 + 图谱补充关联信息，合并后注入 context。

## 记忆整合：从碎片到知识

长期记忆用久了积累大量碎片（同主题十几条、重复、过时、矛盾），检索噪音越来越大。**记忆整合**定期「清理和升华」：

1. **去重**：语义相近的多条合并成更完整版本（「用户喜欢简洁的代码」「用户说过代码要精简」「用户要求不要冗余代码」→ 合并为「用户偏好简洁精练的代码风格，反对冗余」）；
2. **冲突消解**：两条记忆矛盾时（「用户偏好 Python」vs「最近转用 Go」）保留时间更新的、标记旧的过期——**时间戳非常关键**；
3. **抽象提炼（最有价值）**：把情节记忆转化为语义记忆。三次「动态渲染网站 requests 失败换浏览器自动化」的经历 → 蒸馏出「目标网站有动态渲染时，基于 HTTP 的简单请求库往往拿不到完整内容，需要用浏览器自动化工具」这条通用规律。**可用 LLM 自动完成：把一批相关情节记忆喂给 LLM 总结出通用知识，作为新语义记忆存入**。

**节奏**：每次任务结束后轻量级去重更新；每隔一段时间（每天/每周）深度整理提炼，批量情节 → 语义。Mem0 等框架已内置后台异步整合逻辑。

## 完整记忆模块的「读 → 用 → 写」闭环

1. **任务开始前「读」**：从实体记忆取结构化偏好 + 用任务描述做长期记忆语义检索，拼进 system prompt 开头——Agent 带着完整「用户画像」进入任务；
2. **任务执行中「用」**：短期记忆（messages）全程工作，每步内容追加；某步需要专业知识时临时发起长期记忆检索（「查记忆」封装成 Tool，用完即走）；
3. **任务结束后「写」**：新偏好 → 更新实体记忆字段；有价值结论 → 摘要写入长期记忆（embedding 入向量库）；短期记忆清空，工作台恢复干净。

**价值**：Agent 用得越多积累越厚，越来越「了解」用户。

## 面试总结

四层分类说清楚（感知/短期/长期/实体，各自载体与生命周期）→ 三个工程核心问题（存什么——只存对下次任务有价值的；怎么存——语义用向量库、结构化用关系库、混合存储主流；什么时候取——任务前主动检索 + 执行中按需检索）→ 「读→用→写」三阶段闭环收尾。
