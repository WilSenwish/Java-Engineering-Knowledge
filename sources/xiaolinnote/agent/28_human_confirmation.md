# Agent 面试题 28：Agent 应该在什么情况下请求人工确认？

## 核心答案

先看这步是否在**已授权范围内**：目标和参数明确、操作符合执行规则 → 继续执行，不必每调一次工具都确认。需要停下来问的三种情况：**关键对象/要求有歧义**（澄清）、**动作超出原授权**（审批）、**业务规则要求人工审批**。实现上：执行前保存待确认方案 → 用户批准/修改/拒绝 → 批准与具体任务+参数版本绑定 → 恢复时核对方案与当前权限。

## 控制权划分

用户委托 = 目标（完成什么）+ 授权（可采取哪些操作）+ 执行规则（身份环境允许做什么）。Agent 在边界内自主选择步骤；**改变目标、扩大操作范围、决定未明确的关键参数时，控制权交还人**。「整理报告」含读取资料生成草稿，不当然包含公开发布——发布改变传播范围，不能自行推导授权。

## 三种交互别混为一谈

| 类型 | 缺什么 | 人的输入 | 后续 |
|------|--------|---------|------|
| 澄清 | 信息不完整/含义不明 | 明确含义、对象、要求 | 补齐参数继续形成方案 |
| 审批 | 方案明确但缺授权 | 对具体动作的有效批准 | 执行/修改/停止该动作 |
| 人工接管 | 系统无法继续处理 | 判断或处理能力 | 人带证据接手核查 |

「清理旧文件」的「旧」指修改时间还是已废弃？这是澄清不是审批——先问依据，不是让用户批准一份未确定的删除方案。

## 审批时机 = 已有授权 × 操作后果

1. **查授权覆盖**：授权含操作类型、对象、目的、限制条件。获准生成报告≠获准发送；获准改指定目录≠改其他项目。规则禁止的操作，用户再说同意也不能绕过；
2. **看操作后果**：影响多少对象/是否影响他人/数据是否离开原范围/错误能否恢复/恢复代价。**可恢复性 ≠ 有撤销按钮**（文件能恢复但业务已中断；邮件能解释但收件人已读过）；
3. **读操作也可能越界**：外部服务分析敏感内容扩大数据处理范围；大量查询占资源。不能凭「只读」标签认定在授权内。

已明确授权 + 方案没变 + 规则允许 → 不因「影响大」重复询问。

## 不确定性：先分事实缺口和人的选择

- **事实缺口**（文件是否存在/接口状态/查询报错）→ 程序能查就先查，让决定建立在证据上；
- **人的选择**（要哪个版本/同名联系人指哪位/愿不愿承担影响）→ 必须人表达意图；
- **模型置信度 ≠ 参数正确 ≠ 用户授权**。一句「我有 95% 把握」不能替代授权与事实检查；
- 可逆且影响小的非关键选择可用合理默认值；外部收件人、唯一数据删除范围等关键参数不能猜。

## 有效确认的设计

- 方案至少含：具体动作、对象、关键参数、预期影响（展示收件地址/最终正文/附件版本；批量修改展示完整清单和规则）；
- 批准 = 有边界许可：指定身份 × 指定对象 × 约定条件；参数多可算内容指纹，但指纹不能代替用户可读预览；
- 防预览后内容变化：批准某版本，执行时读对应版本或写入时检查版本条件；
- 记录确认编号、任务编号、批准人、方案版本、决定。

## 状态机与恢复

```text
候选动作 → 等待确认 → 已批准 → 执行中 → 已完成
                ↓
         已拒绝 / 已取消 / 已失效
```

- 状态描述程序走到哪，不是模型说了什么；
- 重复回复防重：请求编号核对 + 事务/条件更新，同一批准只进一次执行；
- **本地去重 ≠ 外部只执行一次**：进程崩溃/响应丢失还要外部接口去重与结果核查；
- 批准 ≠ 有权限：用户愿意改共享文件 ≠ 有写权限；管理员有权限 ≠ 同意这个具体修改。三类检查（批准来源/资源权限/业务条件）不能互相替代；
- 结果未知先查实际状态，再决定是否执行，不能把「是否继续」当事实核查。

## 减少重复确认

保存有效委托范围：动作仍在范围内、方案和条件没变 → 沿用授权。一组明确操作可合并确认（展示完整清单一次批准）。范围授权（只处理某目录/只生成草稿/最多改 N 项）比一句「以后都直接做」可靠。**改善指标不能只看确认次数下降**：还要看有无未授权操作、用户是否常改关键参数（频繁改收件人 = 对象消歧没做好）、等待确认是否阻断任务。
