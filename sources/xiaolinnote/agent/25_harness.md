# Agent 面试题 25：Agent 的 Harness（运行时框架）是什么？怎么设计的？

## 核心答案

**Harness = 围绕模型的运行支撑**：组织调用、执行工具、驱动反馈循环。模型只会「下一步生成什么」，Harness 负责「下一步发生什么」。核心原则：**运行停止 ≠ 任务完成**——循环停下来可能只是没 token 了、被限流了、在等用户，不等于活儿干完了。

## 循环三分支

Harness 主循环每轮处理三种走向：

1. **模型请求工具** → 执行工具，结果回灌，继续循环；
2. **模型等待用户输入** → 暂停，把控制权交还（带上下文）；
3. **完成检查** → 判断是否真的达成目标（不是模型自己说完成就算，见题 23）。

## 上下文 vs 任务状态

两回事，分开存：

- **上下文**：塞给模型的 prompt 材料，可压缩可重建（见题 12 记忆压缩）；
- **任务状态**：计划、步骤进度、证据链，系统权威数据，不受上下文压缩影响。

混淆两者是常见翻车点——压缩上下文把任务进度也压没了。

## 面试要点

- Harness 是 Agent 的「骨架」，模型是「大脑」——面试问框架设计，答的就是这五个模块怎么切分（见题 26）。
