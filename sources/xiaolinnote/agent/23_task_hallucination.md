## 核心答案

先区分三类幻觉：**文本幻觉**（编造事实）、**任务幻觉**（声称完成实际没做/做错）、**工具结果幻觉**（脑补工具返回值）。防任务幻觉的核心是**把「完成」从模型的一句话变成系统验证过的状态**：任务状态机 + 证据链 + 幂等键 + 故障注入评测。

## 任务状态机

```
待处理 → 已规划 → 待授权 → 执行中 → 已执行 → 已验证
```

- 模型只能陈述状态，**状态跃迁由系统依据证据执行**；
- 输出层按状态模板生成：「已执行」≠「已验证」，没到验证状态话术就不允许说「完成」。

## 证据链六要素

任务、输入、工具调用序列、原始返回、产物、验证结果——每个环节留痕，声称完成时必须能拿出完整链条。

## 幂等键

每步操作带幂等键（plan_id/operation_id/message_id），重试不产生重复副作用，也让「做没做过」可查证。

## 故障注入评测

主动造错来验证系统会不会被骗：工具静默失败、返回半截结果、返回格式错误、延迟返回、权限拒绝等十来个场景，看 Agent 是继续编还是如实上报。

## 面试要点

- 根治思路：**完成声明权在系统不在模型**；
- 输出层模板化 + 验证器，是性价比最高的两道闸。
