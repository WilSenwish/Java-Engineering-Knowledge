## 核心答案

以「修复一个登录 Bug」为例，五模块切分：**运行协调器**（主循环）、**上下文装配器**（拼 prompt）、**工具执行器**（跑工具）、**状态存储**（任务状态+checkpoint）、**验证器**（判断真完成）。设计主线：模型只出决策，状态跃迁和完成判定权在系统。

## 五模块

| 模块 | 职责 | 关键设计 |
|------|------|---------|
| 运行协调器 | 主循环：调模型→分发结果→决定下一步 | 循环三分支（工具/等待/完成检查），最大轮次熔断 |
| 上下文装配器 | 组装 system prompt、历史、工具结果 | 预算控制+压缩（题 12），与任务状态分离 |
| 工具执行器 | 执行工具调用 | 结果三态：成功/失败/**未知**（超时等未决） |
| 状态存储 | 任务状态、计划、证据链、checkpoint | 定期存档，恢复时先核对未决操作 |
| 验证器 | 验收条件检查 | 跑测试/查状态，**对抗模型「改断言」** |

## 工具结果三态

「未知」态最容易被忽略：工具超时了，可能执行了也可能没执行。恢复流程必须先核对未决操作（幂等键查证），再决定重试还是跳过。

## 验收条件对抗「改断言」

让模型修 bug，它可能顺手把测试断言改了让测试通过。验证器必须：改动 diff 审查范围限定（测试文件变更需额外审批）、验收条件由系统持有而非模型可篡改。

## 面试加分项

- 画出五模块数据流，讲清 checkpoint 恢复时序；
- 主动提「运行停止≠任务完成」（题 25）和状态机（题 23）串起来讲。
