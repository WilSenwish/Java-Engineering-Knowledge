## 核心答案

上下文太长会撞爆 token 上限、成本飙升、延迟变长、模型注意力分散，必须压缩。四类方法：**滑动窗口**（硬截断）、**摘要压缩**、**重要性过滤**、**结构化抽取**。压缩阈值 = 上下文预算 × 触发比例（通常 70%~80%），配合主动监控，不要等爆了才压。

## 四类压缩方法

### 1. 滑动窗口（Sliding Window）

只保留最近 N 条消息或最近 N 个 token，更早的直接丢弃。最简单，但「金鱼记忆」式硬截断——早期任务目标、关键约束可能被丢掉，Agent 做着做着忘了初衷。

### 2. 摘要压缩（Summarization）

把历史对话让 LLM 总结成一段摘要，用摘要替换原始历史。**层级式摘要**：先分段摘要，再把多个分段摘要汇成总摘要，避免单次总结丢细节。

### 3. 重要性过滤（Importance Filtering）

按消息重要性打分，保留高价值的（用户指令、关键决策、工具报错），丢弃低价值的（寒暄、重复确认）。工程上的两种落地形态：

- **观察遮蔽（Observation Masking）**：工具调用返回的大段结果，只留结论/关键字段，遮蔽原始观测细节；
- **主动压缩（Proactive Compression）**：不等爆窗，在每轮结束或达到软阈值时提前触发压缩。

### 4. 结构化抽取（Structured Extraction）

把对话里的关键信息抽取成结构化状态（如 JSON：目标、已完成步骤、待办、约束），任务继续时用结构化状态 + 近期原文拼接，而非全量历史。

## 阈值怎么定

- **上下文预算**：模型窗口留 20%~30% 余量给输出和新工具返回；
- **触发比例**：达到预算的 70%~80% 即触发压缩，而不是 100%；
- **分级策略**：软阈值触发摘要，硬阈值触发窗口截断兜底。

## 压缩 vs Prompt Caching

两者是**互补关系而非替代**：Prompt Caching 是计算层优化（相同前缀命中缓存，费用约为重算的 1/10），压缩是信息层取舍（减少 token 总量）。压缩后前缀仍可能命中缓存，两个一起用。

## 选型参考

| 策略 | 实现成本 | 信息损失 | 适用场景 |
|------|---------|---------|---------|
| 滑动窗口 | 极低 | 高 | 简单对话、短任务 |
| 摘要压缩 | 中 | 中 | 长对话、多轮任务 |
| 重要性过滤 | 中 | 低-中 | 工具密集、观测冗长 |
| 结构化抽取 | 高 | 低 | 复杂长任务、需恢复现场 |

工程上常组合：结构化抽取保任务骨架 + 滑动窗口保近期细节 + 摘要压缩过渡中间段。
