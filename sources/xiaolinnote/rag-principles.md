## 1. 什么是 RAG

**大模型的三个知识困局**：
1. **知识有截止日期**：训练数据有时间窗口，之后的事不知道或开始编；
2. **不知道私有数据**：公司文档、制度、客户信息不在训练集中；
3. **会幻觉**：自信地说出听起来专业但纯编造的内容（医疗/法律/金融不可接受）。

**RAG（Retrieval-Augmented Generation，检索增强生成）** = 给大模型「开卷考试」：
1. 先从外部知识库**检索**相关资料；
2. 检索结果作为**增强**上下文与问题一起给模型；
3. 模型基于真实资料**生成**回答。

历史：2020 年 Facebook 提出 → 2023 年 ChatGPT 爆红后成为企业落地标配。

**RAG 不能**：改变推理能力、改变输出风格、保证 100% 准确。与微调、Prompt Engineering **互补而非替代**。

## 2. 整体工作流程

**索引阶段（离线）**：文档加载（PDF/Word/HTML → 纯文本）→ 文档切割 Chunking → 向量化 Embedding → 存入向量数据库。

**查询阶段（在线）**：用户提问 → 问题向量化（**同一 Embedding 模型**）→ 相似度检索 Top-K → 构造增强 Prompt → 大模型生成。

最基础流程即 **Naive RAG**；生产还会加查询改写、多路召回、Re-rank 等。

## 3. 微调 vs RAG

| 维度 | 微调 | RAG |
|------|------|-----|
| 本质 | 闭卷考试（知识内化到参数） | 开卷考试（外挂参考书架） |
| 知识更新 | 重新训练，成本高周期长 | 替换知识库文档重新索引，模型不动 |
| 准确性 | 靠记忆，可能记错 | 基于真实文档，可追溯 |
| 风格控制 | **强项**（文言文/客服话术） | 有限（检索内容只是参考） |
| 成本 | 初始高（训练数据+GPU），推理低 | 初始低，每次查询有检索开销和 token 消耗 |

微调分级：全量微调（效果最好成本极高）/ LoRA 参数高效 / 指令微调。**成熟做法：微调 + RAG 结合**——微调适应领域风格，RAG 提供实时知识。

## 4. 文档切割策略

两难：切太小丢上下文，切太大降精度且浪费窗口。

| 策略 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 固定大小切割 | 每 500 字符一块 + 重叠 10-20% | 简单可预测 | 破坏语义结构 |
| **递归字符切割** | 分隔符优先级 `["\n\n","\n","。","！","？","；","，"," "]` 逐级降级 | 最常用（LangChain RecursiveCharacterTextSplitter） | 仍可能不完美 |
| 文档结构切割 | Markdown 按标题、代码按函数类、HTML 按标签、PDF 按页 | 语义完整 | 仅适用格式规范文档 |
| 语义切割 | 相邻句子 Embedding 余弦相似度，相似度骤降处下刀 | 质量最高 | 计算成本最大 |
| Agent 智能切割 | LLM 审视初始块决定合并/拆分 | 理论最好 | 成本最高 |

**实战建议**：起步用递归字符切割 256-512 tokens + 10-20% 重叠；有清晰结构切结构切割；进阶用**父子块策略**——存小块精准检索、返回含上下文的父块给大模型。

## 5. Re-rank：两阶段检索

**问题**：向量检索用 Bi-Encoder（查询和文档分别编码），文档编码时不知道用户会问什么 → 信息压缩损失 + 缺乏查询意图感知。

**方案**：Cross-Encoder 把查询和文档拼一起 `[CLS] query [SEP] doc [SEP]` 送 Transformer 深度交互。但太慢（1000 万文档 = 1000 万次推理），所以**两阶段**：
1. 第一阶段 Bi-Encoder 快速召回 **Top-50~100**（追求召回，宁可多捞）；
2. 第二阶段 Cross-Encoder 精排到 **Top-5~10**。

主流 Re-rank 模型：Cohere Rerank（商业 SaaS）、BGE-Reranker（开源标杆，中文好，可私有化）、ms-marco-MiniLM（轻量）、Jina Reranker（多语言）、bce-reranker（网易双语）。

**提升幅度**：复杂多跳查询 +40-50%；简单事实 +18%；模糊查询 +30-40%；Databricks 测试幻觉率降低约 35%。可条件触发（初排 Top-1 分数低于阈值才启动）。

## 6. Embedding 算法演进

| 代际 | 代表 | 关键特性 |
|------|------|----------|
| 第一代（2013） | Word2Vec（CBOW/Skip-Gram）、GloVe、FastText | 静态词向量，可做类比运算「国王-男人+女人≈女王」；**无法处理多义词** |
| 第二代（2018） | BERT | 双向上下文，同词不同向量；MLM+NSP 预训练；取 `[CLS]` 作文本向量；窗口 512 |
| 第三代（2023+） | **BGE-M3**、OpenAI text-embedding-3 | M3 = 多粒度（8192 tokens）+ 多功能（稠密/稀疏/多向量三合一）+ 多语言（100+）；text-embedding-3-large 维度 3072 |
| 第四代（2025） | LLM2Vec、Qwen3-Embedding、Seed1.5-Embedding | 大模型直接做 Embedding，需专门训练；Seed1.5 达中英文 MTEB SOTA |

**选型**：看 MTEB 榜单；中文场景优先国产（BGE/M3E）；长文档选 8192 窗口；私有化选开源。

## 8. 向量数据库

核心：HNSW/IVF/PQ 索引实现毫秒级 ANN 搜索，用空间换时间。

- **HNSW**：多层导航图，粗到细几跳定位（最常用默认）；
- **IVF**：先聚类分桶只搜相关桶，内存效率高但损失召回；
- **PQ**：向量分段压缩存储，内存受限场景，常与 IVF 结合。

| 数据库 | 定位 | 适用 |
|--------|------|------|
| Milvus | 十亿/百亿级规模，索引丰富有 GPU 加速 | 企业级大规模首选（需 K8s 运维能力） |
| Pinecone | 全托管 SaaS 零运维 | 不想折腾基础设施（付费、数据在第三方） |
| Weaviate | 原生混合检索（向量+BM25） | 中小规模混合检索开箱即用 |
| Chroma | 轻量 Python 原生 | POC/教学（无分布式无安全机制） |
| Qdrant | Rust 编写单机性能极强 | 高性能自建但不想太重 |

**趋势**：已有 PG/ES 的团队用 `pgvector` / ES 向量扩展，中小规模够用且运维成本几乎为零。

## 9. 多路召回

单路向量检索短板：精确匹配弱（产品编号 PRD-2024-089 无语义匹配不上；iPhone 15 与 14 语义太像分不清）。

**三路召回**：向量（语义）+ BM25 关键词（精确）+ 知识图谱（实体关系）。

**RRF 融合（Reciprocal Rank Fusion）**：不看绝对分数只看各路排名，被越多路命中综合得分越高。混合检索比单路好 10-30%。

**高级策略**：查询改写（Query Rewriting）、HyDE（先生成假设性答案文档再检索）、Multi-Query（多角度子问题分别检索）。

## 10. RAG 效果量化

**检索指标**：Recall@K（找全没）、Precision@K（找对没）、NDCG（排得对不，最综合）、MRR/MAP。

**生成指标**：
- **Faithfulness 忠实度**（最重要）：回答每个陈述能否从检索文档找到支撑（RAGAS 拆陈述验证）；
- Answer Relevance 答案相关性：有没有答非所问；
- Context Relevance 上下文相关性：检索文档是否相关。

**RAGAS** = RAG 评估事实标准（LLM-as-Judge）。其他：DeepEval（CI 单测化）、TruLens（可观测）、ARES（合成评估数据）。最佳实践：先建基线、测试数据有代表性、定期评估、自动化进 CI/CD。

## 11. 大模型幻觉与防幻觉体系

**幻觉**：不知道但假装知道，用流畅自信的语言编造。Karpathy：「幻觉正是大模型所做的一切，是造梦机；只有进入事实不正确领域才被标记为幻觉。这不是 bug。」

类型：事实性幻觉（内在=与输入矛盾/外在=无法验证）+ 忠实性幻觉（RAG 场景，模型偏离正确检索文档）。

**RAG 降幻觉机制**：闭卷变开卷；注意力权重偏向检索文档（70-80%）；可追溯。研究表明降低事实性幻觉 20-40%，但**不能完全消除**。

**四层防幻觉体系**（分层设防、按需组合）：

| 层 | 手段 | 成本 | 场景 |
|----|------|------|------|
| 第一道 | Prompt 工程约束（限知识范围/标来源/鼓励说「不确定」/结构化推理） | 零成本 | 所有场景 |
| 第二道 | RAG 检索增强 | 中 | 需准确知识标配 |
| 第三道 | 输出验证（LLM-as-Judge 交叉验证/规则引擎校验关键数据/多次采样一致性） | 增延迟 | 医疗法律金融高风险 |
| 第四道 | 领域微调 + 不确定性量化（logprobs/采样一致性/内部状态熵） | 最高 | 极高准确性要求 |

**风险分级管控**：高风险（医疗法律金融）= RAG+人工审核+免责声明；中风险（客服内容代码）= Prompt+RAG+输出验证+置信度阈值；低风险（头脑风暴草稿）= 基础 Prompt。**核心原则：把幻觉当工程问题而非模型缺陷。**
