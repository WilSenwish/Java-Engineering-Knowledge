# AI 编程面试题 13：跨会话继续开发时，如何让 AI 接续需求、代码状态和任务进度？

## 核心答案

把未完成的开发当**工作交接**处理：

1. **结束前保存实际成果 + 交接记录**：当前需求、必须保留的约定、已确认方案、哪些代码已实现/只写一半/没验证；工作区位置、版本、未提交文件。**AI 在对话里展示过代码 ≠ 文件里已有内容**；
2. **新会话先读记录再核现场**：读交接记录和项目规范 → 核对当前目录、代码差异、新增文件、相关实现；**交接记录是恢复线索，实际工作区可能已变**（别人改过/换目录/服务状态变了）；冲突时区分记录过期与代码不符合需求；
3. **运行状态重新确认**：依赖/开发服务/测试条件；**之前执行过的命令不能当初始化步骤全部重放**——创建任务/启动服务/改数据的命令先查当前状态再决定继续、恢复还是补做（「把昨天命令重跑一遍」= 又按了一次新游戏：服务多起一份、任务又建一单）；
4. **从明确未完成项入手**：先做相关检查再继续修改验证；每完成一阶段更新交接记录；
5. **接续成功看行为和进度对得上**，不是 AI 复述出昨天总结。

## 需要接上的三部分

| 部分 | 包含 | 只恢复它可能遗漏 |
|------|------|----------------|
| 需求与决策 | 目标/约束/验收/方案/未解决问题 | 知道怎么写不知哪些行为必须保留 |
| 实际开发成果 | 源码/测试/配置/未提交修改/新文件 | 有计划总结拿不到已写出的实现 |
| 执行与验证状态 | 环境准备/服务状态/执行结果/已产生的任务数据 | 代码齐全但无法运行或重复已执行操作 |

「创建导出任务已完成」可能指函数写完/单测通过/真实接口建过任务——**三个状态决定下一步不同动作**，记录要说明到哪层。

## HANDOFF.md 关键要素

```markdown
## 目标与当前约定（引用 spec.md/plan.md，不复制历史对话）
## 交接的代码现场（工作目录/基线版本/未提交修改/未跟踪新文件）
## 进度与未完成项（区分：已实现/单测已跑/草稿未跑/未验证）
## 验证记录（命令/结果/条件——仓库替身通过 ≠ 真实接口通过）
## 运行状态（服务是否还在跑/样例任务 demo-export-17 先查状态再重放）
## 下一步
```

- 未跟踪文件单列（换工作区时只带提交会丢掉真正要改的半成品）；
- 测试记录写范围条件（替身下的单测通过不能证明完整导出通过）；
- 运行状态写「恢复时先查询该任务当前状态，不直接重放创建请求」——保留查询入口而非重复制造现场；
- 整理提示词要求先核对实际保存的文件和执行结果再写记录（防把旧计划写成已完成）+ 不补造完成结果 + 不为交接重放业务操作。

## 新会话核对工作区

```bash
pwd && git rev-parse --show-toplevel   # 当前目录和工作树根
git rev-parse HEAD                     # 当前提交
git status --short --untracked-files=all
git diff && git diff --cached          # 未暂存 / 已暂存改动
```

- 新建未跟踪文件不出现在 diff 里，要直接读内容；**被忽略的必要资料（测试输出）也要查是否存在**；
- 项目名相同 ≠ 同一工作区（可能是另一工作树/分支/版本）；
- 记录与代码不同 → 记录落后补依据更新状态；代码违反需求记待修复；**业务规则说明应该怎样，源码说明现在怎样，不能混成一项事实**；
- 未交接的修改：无关保留、相关补读重验，不为对齐昨天记录覆盖当前内容。

## 运行状态与已执行动作

- 新终端无旧环境变量；旧服务可能仍占端口——**端口有响应只说明那里有服务，可能是另一工作区的旧进程**；
- 命令按效果分：读取/查询=观察；启动服务/创建任务/改数据=改变现场；
- 样例任务已创建 → 先查是否存在、当前状态、执行结果：已完成→利用结果验证；等待中→继续核对执行模块；需要新样例→明确安排新一轮；
- 旧请求超时 → 不知创建是否生效，按业务标识/查询接口确认，防重复创建；
- 异步中断分三类：进程在跑（观察输出和任务状态）/进程退出任务在队列（按任务机制恢复）/代码执行成功只记录没更新（补证据）；
- 环境暂时无法恢复 → 先核源码/需求/单测，环境相关检查单独记录，**不把环境问题写成功能已完成或完全无法判断**。

## 接续提示词模式

```
继续 X 任务。先读取项目规范、HANDOFF.md 和它引用的需求文档。
确认当前目录、基线、未提交修改与新文件，核对实际源码是否符合记录。
保留当前工作区成果，区分记录过期、实现错误和后续新增变更。
确认环境、服务和测试条件；对样例任务先查询状态，不直接重放创建请求。
核对旧验证结果的适用范围，执行本轮需要的相关检查。
按已确认方案继续未完成模块；每完成一阶段更新代码状态、执行结果和剩余工作。
```

判断接续成功：读取了正确实现、沿用有效约定、补做缺失模块、验证结果对应当前代码。推进后更新任务清单与交接入口（实现写完未跑测试/局部过完整未验证各保留状态），原始输出与版本可找。剩余工作写清下一步核验位置和缺什么条件——下一轮从具体问题继续，不重新猜「剩下的细节」。
