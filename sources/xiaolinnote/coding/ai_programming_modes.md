# AI 编程面试题 1：AI 编程有哪些常见方式？代码补全、对话生成和 Agent 编程有什么区别？

## 核心答案

按 AI 参与开发的方式分三种，判断标准是两点：**AI 能采取哪些行动，以及谁根据执行结果推进下一步**。

- **代码补全**：根据光标附近代码和上下文给候选实现，开发者决定接受/修改/拒绝，开发过程由开发者推进；
- **对话生成**：开发者把需求、约束、相关代码讲清楚，AI 解释代码、讨论方案、生成实现；运行代码、判断问题、反馈结果主要由开发者组织；
- **Agent 编程**：授权范围内把读文件、改代码、运行检查接入任务执行，模型根据工具返回决定下一步（测试失败→查原因→修改→复验）。

**代码长度、聊天界面、单次工具调用都分不清三者**——同一段代码三种方式都能生成；Agent 也能放聊天窗口；单次工具调用只说明取得某种能力，Agent 关注的是「围绕目标根据反馈持续选择行动」。

## 同一任务贯穿：给创建订单接口加数量校验

规则：`quantity` 只接受 1-100 数值整数（含端点），字符串/缺失/小数拒绝，非法输入沿用项目参数错误方式且不写入订单。

**补全**：开发者写好函数签名和注释（规则），模型补全体，开发者自己接入流程、安排检查。候选函数正确≠证明非法请求没写入订单。

**对话**：把规则、接入位置、错误语义讲清，附当前源码；AI 讨论实现。回归发现「数量 0 返回错误但订单写入次数为 1」——局部校验正确、接入流程有问题，带着错误结果+写入次数一起反馈下一轮。

**Agent**：给目标+范围+完成依据，Agent 自己读源码确定接入位置、修改、跑检查；发现写入次数异常→核对执行顺序→把校验移到写入前→复验。**执行结果直接进入任务推进过程**；模型生成「测试通过」不会让测试真执行——要看工具返回的实际结果。

## 对比表

| 比较内容 | 代码补全 | 对话生成 | Agent 编程 |
|---------|---------|---------|-----------|
| 开发者给出的起点 | 当前编辑位置、注释与上下文 | 规则、相关代码和问题 | 目标、范围、规则与完成条件 |
| AI 主要提供 | 候选代码 | 解释、实现与接入建议 | 文件修改、工具操作与执行反馈 |
| 谁组织接入和检查 | 开发者 | 开发者为主 | 模型在授权范围内安排工具执行 |
| 出现写入次数错误后 | 开发者排查继续编辑 | 开发者带回事实再讨论 | 模型可依据失败补读、修改并复验 |

三种方式不互斥：对话可进入 Agent 执行，Agent 改完可继续用补全处理细节。

## 交付判断（不因方式降低标准）

同一份依据：允许数值被接受、不允许的类型范围被拒绝、错误方式符合约定、非法输入没写入、原合法流程正常。补全被接受≠功能正确；对话解释通顺≠方案可行；**Agent 宣布完成还要与实际修改和执行结果对应**。只跑校验函数测试没观察写入次数——验证要求来自任务行为。
