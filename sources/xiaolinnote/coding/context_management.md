# AI 编程面试题 11：AI 编程的上下文越来越长时，如何保留关键信息？

> **来源站点**：小林面试笔记（xiaolinnote.com）

> **抓取日期**：2026-10-20
> **所属知识域**：域6 性能优化与架构演进（AI 前沿）
> **板块**：AI 编程面试题（14 题）· 上下文管理

## 核心答案

1. **围绕下一步整理当前状态**：保留目标、不能违反的约束、当前方案、代码改到哪、验证结果、剩余问题；重复讨论和大段源码日志压缩成结论 + 保留读取位置；
2. **摘要不写「已完成测试通过」**：区分代码已修改与行为已验证，记录测试对应的版本/工作区状态、修改后有没有重跑；旧方案已替换、某原因只是猜测也要标明；
3. **核心状态放简短 Markdown**（如 context.md），详细规则/源码/原始结果留在各自位置；
4. **用时要确认内容已进入模型当前输入**——**文件存在 ≠ 模型读过**（写在 context.md 但没打开 = 锁抽屉里隔着抽屉背诵）；
5. **阶段变化时更新摘要**：修订而非末尾追加；续做前让 AI 复述约束与下一步，对照原始材料核验。

## 聊天还在为什么还漏要求

- 模型一次生成依据的是**工具为这次请求组织的上下文**——界面能翻到的聊天记录不一定会原样进入每次请求（工具可能整理历史/缩短输出/摘要）；
- 窗口有 Token 容量限制；装得下 ≠ 会正确使用每个条件（长上下文研究中位置和长度影响检索表现）；
- **历史内容互相冲突**（前面讨论同步导出后来改异步；旧测试通过随后代码又改）——模型需要知道哪些仍有效；
- 换大窗口缓解容量，不解决失效方案和规则冲突；「别忘了之前的要求」没说清哪些要求仍采用。

## 该留什么（判断标准）

**没有这条信息，AI 会不会选错方案、破坏约束、重复已完成的工作、把未验证代码当可交付？**

| 保留 | 避免 |
|------|------|
| 当前目标、范围与验收条件 | 做偏需求、无依据扩大范围 |
| 必须保留的业务与接口约定 | 新功能破坏原有行为（如漏数据归属） |
| 当前方案及关键选择依据 | 恢复已放弃方案、重复已决争论 |
| 当前代码状态与相关位置 | 重复修改、漏模块、误读旧实现 |
| 验证结果、条件与剩余缺口 | 旧结果/未执行检查/局部验证当整体通过 |
| 未解决问题与下一步检查 | 在猜测上继续实现 |

关键细节往往很短却改变结论：「不」「仅」「尚未」「修改前」「用户已确认」不能为精简删掉。区分事实/约定/推测：「需求规定只导出本人订单」是行为要求、「代码已加用户条件」是实现状态、「真实接口是否遵守」需验证——都写成「已处理」就无法判断还缺什么。

## context.md 示例（订单导出）

```markdown
## 目标与必须保留的约定
新增异步导出任务，只导出当前用户自己的订单。用户身份沿用已有认证结果，
不接受请求参数指定其他用户。规则位置：specs/order-export/spec.md。

## 当前方案
用户已确认异步任务，之前讨论的同步返回 CSV 方案已替换。

## 当前代码状态
状态节点 S2：用户范围条件调整后，相关测试尚未重跑。
src/order/export_job.js：createExportJob 已编写，最新调整需要核验。
src/order/export_worker.js：导出执行模块尚未实现。

## 验证依据与缺口
S1 时运行 node --test ... 通过；S1 之后改了用户范围条件，
这条结果不能证明 S2 已通过。完整导出与真实接口尚未验证。
```

要点：**S1/S2 状态节点区分两次代码状态**——旧测试结果不能直接复用；不复制源码但指明继续核验的入口；「怀疑问题出在执行模块」保留为待核实线索，不改写成「存在缺陷」。

## 省略与回查

- 摘要保留结论 + 读取位置；原始材料留仓库/文档/执行记录；
- 读取位置要明确（`src/order/export_job.js` 的 `createExportJob` 比「导出逻辑」有用）；
- 偶发故障输出只在终端显示 → 保存必要原始记录 + 触发条件；
- **外部保存还要实际读回**：模型不会因为目录里有 context.md 就自动获得内容——显式引用/读取/粘贴，确认已进本轮输入；
- 不为每个小任务建一整套文档，复用现有需求说明/任务清单/执行记录。

## 整理时机与防膨胀

完成一个阶段/切模块/需求调整/重复信息增多时整理（不必等窗口满）。**修订原有状态而非末尾追加**（同步方案已替换就在「当前方案」写明异步；S2 测试重跑了就更新验证状态）。提示词让 AI 整理时限定「只更新状态记录不改业务代码」+ 要求区分「代码已修改 vs 行为已验证」+ 不补造执行结果。

自动压缩后仍要核对是否留下关键约束；丢失重要信息回原始需求/源码/记录恢复。整理后检查：让 AI 复述目标/硬约束/最新代码状态/下一步验证什么——**复述正确只说明能回答，后续行动是否遵守才是真的用了**。
