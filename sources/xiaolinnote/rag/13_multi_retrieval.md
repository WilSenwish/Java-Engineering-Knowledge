# RAG 面试题 13：什么是多路召回？具体怎么做？

## 核心答案

多路召回 = 同时用多种检索方式捞候选再合并排序。出发点：**没有任何一种检索方式全能**——向量管语义（同义词/不同表达），BM25 管精确词（型号/缩写/数字），多 Query 扩展管表述角度差异。三路结果 RRF 融合后再送 Rerank 精排。调大 top-K 不是解法——向量相似度排序尾部很平，Top-20 和 Top-200 只是多塞无关 chunk，正确答案照样进不来，反而稀释 LLM 注意力。

## 三路分工

| 路 | 擅长 | 短板 | 适合 |
|----|------|------|------|
| 向量检索（Dense） | 语义相似、同义词、表达差异 | 精确词/数字/专有名词 | 通用语义检索 |
| BM25（Sparse） | 精确词、专有名词、数字 | 同义词、词不重叠的语义相关 | 大量精确词的知识库 |
| 多 Query 扩展 | 覆盖不同表述角度 | 增加 LLM 调用开销 | 用户提问风格多变 |

BM25 中文实现：jieba 分词 → 词列表建索引 → 查询切词算分。核心逻辑：「词在这篇文档出现多（词频高）但整个知识库出现少（区分度高）→ 这个词代表了这篇文档」。

多 Query 覆盖率提升：用户提问风格多变场景（客服问答）召回覆盖率 +10%~20%。

## RRF 融合细节

各路分数单位不同（余弦 0~1 vs TF-IDF 任意正数）没法直接加权；归一化不稳（分布差异大）。**RRF 只用排名**：`score = Σ 1/(k+rank)`，k=60 是实践最稳经验值（保底分，不让排名靠后候选因偶尔失误被完全淘汰）。本质还是粗排——精度要求高就在 RRF 后接 Cross-Encoder 精排（如 bge-reranker-v2-m3）。

## 实战组合建议

- 电商/IT 文档（大量型号数字）：向量 + BM25 双路标配；
- 客服问答（提问多变）：加多 Query 扩展；
- 质量要求极高：三路全上 + Rerank 收尾。
