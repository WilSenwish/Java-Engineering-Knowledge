# RAG 面试题 17：如何规避 RAG 系统中大模型的幻觉？

## 核心答案

RAG 幻觉有两个**完全不同的来源**，解法不一样：① **检索层幻觉**——没召回到相关内容，LLM 靠自身知识编造（知识库写「7 天无理由退款」，没召回，LLM 用「知识」答「30 天」，用户按错信息操作失败）；② **生成层幻觉**——召回了但 LLM 超发挥，在资料基础上加推断补原文没有的细节（更隐蔽更常见）。四方案：Prompt 强约束 / 检索质量门控（Rerank 低于阈值直接拒答）/ 生成后引用核查 / 结构化输出强制溯源。**Prompt 约束 + 检索门控成本最低收效最快，上线前必须做；治幻觉先治检索**。

## 方案一：Prompt 强约束（治生成层）

四条规则各有道理：只能使用参考资料信息（让 LLM 知道边界——「你是传话人不是百科全书」）；资料没有必须说「无法回答」（给合法逃生出口，优雅认怂比编合理答案好）；标注信息来源（回答时主动对照原文 = 自检动作）；不推断不猜测不补充。但对检索层幻觉帮助有限——prompt 里根本没相关内容，再强约束也拦不住瞎编。

## 方案二：检索质量门控（治检索层）

Rerank 模型给每个候选打 0~1 相关度分，**最高分低于阈值直接返回「知识库无相关信息」，不让 LLM 在低质量上下文硬撑**。阈值调法：拿「已知答案在库」和「已知答案不在库」的测试集跑 Rerank 分数分布，找分开两类的切点。经验值 0.3~0.6：精度要求高（金融医疗）偏高，召回宽松（闲聊）偏低。**答错比不答更危险**——「我不知道请联系人工」比自信的错误答案好得多。

## 方案三：生成后引用核查（事后审稿）

LLM 生成后，另一个（或同一）LLM 当编辑回头逐条核查：每条关键信息在 chunk 里有没有依据，无依据标「无法核实」或删掉。代价：多一次 LLM 调用，延迟增加成本翻倍——只用于医疗问诊、法律咨询这种容错极低的场景。

## 方案四：结构化输出强制溯源（格式层约束）

让 LLM 输出 JSON，每条结论必须填来源编号：

```json
{
  "answer": "完整回答",
  "statements": [
    {"claim": "具体结论1", "source_ids": [1, 2]},
    {"claim": "具体结论2", "source_ids": [3]}
  ],
  "confidence": "high/medium/low"
}
```

两个生效原因：① 构建 JSON 时必须主动想「这条从哪条资料找到」——像学生写论文必须标参考文献自然不敢编；② 系统可程序化验证 source_ids 编号真实存在且与 claim 相关，不相关自动过滤。

## 场景组合

- 普通知识库/客服：方案一+二（基础配置，成本极低）；
- 金融/法律（可信度要求高）：加方案四（来源编号用户可核实）；
- 医疗/合规（容错极低）：四方案全上，用延迟和成本换最高准确性。
