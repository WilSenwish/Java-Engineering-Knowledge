## 核心答案

系统性四层框架：**索引层**（知识怎么存）、**查询层**（问题怎么转）、**召回层**（从哪些路径找）、**重排序层**（最终谁进 prompt）。检索是 RAG 命脉——LLM 只能根据送进的 context 回答，**检索召回内容就是系统天花板**；生成层优化（调 prompt/换模型）是锦上添花，检索层优化是从根本提升上限，投入产出比最高没有之一。典型生产组合：**Parent-Child 索引 + 向量 BM25 多路召回 + Rerank 精排**，提问质量差再加 Query 改写。

## 索引层：Small-to-Big 解粒度矛盾

chunk 两个角色天然矛盾：「被找到」要小粒度语义聚焦（整篇压一个向量混合太多语义，细节问题匹配不上）；「被读懂」要大粒度上下文完整（术语定义在前段、解释在后段，只给后段 LLM 看不懂）。三种实现：

- **Parent-Child Chunking**：子 chunk（150 token）建向量索引检索，命中后按 parent_id 取父 chunk（500 token）给 LLM——检索用小的，阅读用大的；
- **摘要索引**：LLM 为每段生成摘要，用摘要建索引（摘要是核心意思提炼，语义更聚焦命中率高），命中后返回原文；
- **多粒度分层索引**：章节级/段落级/句子级三层，按问题类型选粒度（「什么是 RAG」用章节级，「退款几个工作日」用句子级）。

## 查询层：四种加工

Query 改写（口语→书面、指代补全）/ 多 Query 扩展（3-5 角度分别检索合并，**原始问题一定要保留在检索列表**——改写可能丢原始细节，原始问题反而最精准）/ HyDE（假设答案当检索代理，知识库领域明确的场景效果稳，方向错了会带偏）/ Step-back（具体问题抽象成背景问题，两步走比直接查准）。

## 召回层：多路 + RRF

向量（语义）与 BM25（精确词）盲区互补，三路并行，RRF 按排名融合（k=60）。各路分数量纲不同不可比，排名是通用语言——像百米和游泳成绩单位不同但排名可比。

## 重排序层：Cross-Encoder

Bi-encoder（query/chunk 独立编码算余弦）快但看不到两段文字的具体词语关联；Cross-encoder（query+chunk 拼一对输入）能看到 query 每个词对 chunk 的影响，精度远高但每候选单独跑一次只适合小候选集。**类比：Bi-encoder 看简历判断合不合适，Cross-encoder 把两人放一房间观察怎么交流**。多路召回 20~30 候选 → Rerank 取 top-3~5。开源：BGE-Reranker-v2、BCE-Reranker；API：Cohere Rerank、Jina Reranker。不加 Rerank 的问题：token 消耗暴涨 + 长上下文「Lost in the Middle」（只关注开头结尾，中间被忽略）。

## 四层记忆法

索引层保证「存进去的知识可以被找到」，查询层保证「搜索姿势是对的」，召回层保证「不漏掉该找到的」，Rerank 层保证「送进 LLM 的是真正有用的」。
