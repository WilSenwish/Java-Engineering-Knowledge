# RAG 面试题 15：了解哪些更复杂的 RAG 范式？

## 核心答案

RAG 三代演进：**Naive RAG**（提问→向量检索→拼 prompt→生成，啥都没优化）→ **Advanced RAG**（检索前 Query 改写/扩展 + 检索后 Rerank/压缩，固定流程上打补丁，大多数生产系统的形态）→ **Modular RAG**（各环节拆成可替换模块乐高式组合，LlamaIndex Workflow / LangGraph 即此思路）。之上的四个高级范式针对朴素 RAG 三大痛点（检索质量参差/所有问题同一套流程/知识库覆盖盲区）：

| 范式 | 核心创新 | 痛点 | 复杂度 |
|------|---------|------|--------|
| Self-RAG | LLM 自主决策要不要检索 + 评估质量 | 流程死板 | 高（需特殊训练模型） |
| CRAG | 检索质量差时自动降级网络搜索 | 知识库盲区 | 中 |
| GraphRAG | 社区发现+层次摘要支持全局查询 | 向量只能局部匹配 | 高（图构建+摘要成本） |
| Agentic RAG | 多轮动态检索 | 复杂问题一次检索不够 | 中（Agent 框架） |

## Self-RAG

四种 reflection token：Retrieval（要不要检索）/ Relevance（召回内容相不相关）/ Support（答案有没有文档支撑防幻觉）/ Utility（答案有没有用）。流程：判断是否需要检索（常识问题直接答）→ 逐条评估召回 chunk 相关性 → 相关 chunk 各生成候选答案 → 打支撑分和有用分 → 选最优。**关键前提：四种 token 不是现成 LLM 自带，需专门构造数据集监督微调训进去**——不能拿普通 GPT-4 直接套用，要么用论文开源微调版（Llama2-7B/13B）要么自己造数据微调。好处：不需检索的省开销，结果不相关能识别避免基于错误上下文幻觉。

## CRAG（Corrective RAG）

检索后加质量评估器（轻量分类模型或 Rerank 分数近似），三级路由：**相关** → 直接用本地结果；**不相关** → 丢弃本地降级走网络搜索；**模糊** → 本地+网络结果合并互补。核心价值是兜底——知识库覆盖不到不乱答，把知识库当主力、网络搜索当备胎。

## GraphRAG（微软 2024.7）

两步：① 预处理——LLM 抽取实体关系建知识图谱 → Leiden 社区发现算法聚类成「社区」→ 每社区生成 LLM 摘要（描述实体关系和整体内容）形成多层层次结构；② 检索——局部问题（「A 公司 CEO 是谁」）图谱内实体查找+关系遍历，全局问题（「这些文档主要主题有哪些」）Map-Reduce 各社区摘要提取再汇总。**核心创新是「社区摘要 + Map-Reduce」的系统化组合而非单点发明**——把全局信息提前蒸馏好，查询不需遍历所有文档。代价：构建图谱+社区摘要需大量 LLM 调用。适合企业关系分析、药物-疾病-症状关联、大规模文档主题归纳。

## Agentic RAG

RAG 嵌入 Agent 循环：LLM 自主决定要不要再检索、用什么关键词、结果够不够、何时生成。适合多步骤推理（「分析 A 公司三年财报找出营收增速放缓根本原因」）。设最大迭代次数防死循环。区别：Self-RAG 加「要不要检索」开关，CRAG 加「检索不好怎么办」兜底，Agentic RAG 把整个检索流程变成可循环调整的智能体——**流程不是写死的，LLM 运行时自己决定**。
