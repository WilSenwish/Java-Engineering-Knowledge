# RAG 面试题 10：你使用 RAG 给大模型一个输入，系统是怎样的工作流程？

## 核心答案

不是「检索+生成」两步，而是六步流水线：**Query 预处理 → Query Embedding → 向量检索+多路召回 → Rerank 精排 → Prompt 拼装 → 生成+溯源**。核心目标只有一个：让大模型回答时有真实知识依据，而不是凭空发挥。

## 六步详解

**① Query 预处理**：用户原始提问质量决定后续所有环节天花板。口语化/指代问题（「上次那个方案怎么样」）直接检索效果极差。三种技术：简单改写（口语→正式检索句）、**HyDE**（LLM 先生成假设答案，用答案向量检索——问题和答案用词差异大，但假设答案和真实答案语义空间更匹配）、多角度扩写（1 个问题扩 3-5 种表述分别检索合并）。

**② Query Embedding**：必须用和离线建库**完全相同的 Embedding 模型**——不同模型训练数据/目标函数/维度/向量空间形状都不同，A 建的库用 B 检索就像北京坐标系和 WGS84 混用，距离计算无意义。**换模型 = 整个知识库重建**。

**③ 向量检索 + 多路召回**：ANN 找余弦相似度 Top-K，几十毫秒。但单路不够——向量对精确词（产品型号/专有名词/错误拼写）弱，BM25 对精确匹配强，两路互补，**RRF（互倒排名融合）合并**。例：「LSTM 和 Transformer 的区别」，向量找「序列模型对比」语义内容，BM25 精准命中含这两个词的文档。

**④ Rerank 精排**：粗排 Top-20 混入干扰项，Cross-Encoder 把 query+候选拼一起深度打分，留 Top-3~5。**不对百万数据直接 Rerank 的原因**：Cross-Encoder 每个候选都要拼接过模型，计算量大得多——「粗排筛到几十条，精排再从几十条挑最好几条」两阶段兼顾速度质量。Rerank 几百毫秒内，质量提升明显。

**⑤ Prompt 拼装**：每条指令都有工程意图——「只根据资料回答」抑制凭记忆发挥（模型天生喜欢「帮忙」，资料没有也会编）；「资料没有就说不知道」防信息不足时强行补全；参考资料带编号为了引用溯源。

**⑥ 生成 + 溯源**：要求标注每句话来自哪个片段（「根据资料[1]...」）。**即使有参考资料，模型仍可能过度发挥或误读**——溯源让用户能判断哪些可靠、哪些要再确认。

## 耗时分布与优化

Query 改写几十毫秒 → 向量检索几十毫秒 → Rerank 几百毫秒 → Prompt 组装可忽略 → LLM 生成 1-10 秒。优化：缓存高频 Query 检索结果；**向量检索和 BM25 并行执行**（两路延迟从串行叠加变取最大值）。
