## 核心答案

RAG = Retrieval-Augmented Generation（检索增强生成）。LLM 训练完知识就冻住了，遇到私有数据或最新信息答不上来。RAG 在生成答案前先去外部知识库检索相关内容，把检索结果和用户问题一起交给 LLM 基于上下文回答。**本质是给 LLM 开卷考试**——不改模型参数，知识放外部实时检索。三大易混淆点：RAG ≠ 搜索 API（漏了 Generation）、RAG ≠ 微调（不动参数）、RAG ≠ 简单「检索+扔给模型」（还有切割/向量化/粗排精排）。

## 离线阶段（只做一次，建库）

1. **文档加载**：PDF/Word/Markdown/网页/数据库记录，用 LlamaIndex/LangChain DocumentLoader；
2. **文档切割（Chunking）**：不能整篇存——向量模型有输入长度限制（几百到几千 token）；且整篇压缩成一个向量，细节被「平均掉」。实践 500~1000 token/chunk + 前后重叠约 100 token；
3. **Embedding（向量化）**：文本 → 高维向量（如 1536 维浮点列表），语义坐标系——语义相似的文本向量位置近。原理是对比学习训练「把相近的拉近、无关的推远」；
4. **入库**：向量 + 原始文本 + metadata 一起存向量数据库（Chroma/Milvus/Qdrant/Weaviate）。

## 在线阶段（每次提问实时执行）

1. **Query 处理**：口语化/模糊问题先改写（如「上次说的那个方案」需从对话历史补充上下文）；
2. **向量检索（粗排）**：问题转向量 → Top-K 相似 chunk，几十毫秒返回；但只比向量距离，无深度语义理解，混入「看着近其实不相关」；
3. **Rerank（精排）**：Cross-Encoder 把问题和候选 chunk 拼一起深度理解相关性重排——粗排像书架扫一眼，精排像翻开读目录。只对粗排 Top-20 精排，留 Top-3~5；
4. **生成**：问题 + 精排 chunk 拼 prompt，明确告知「只根据提供的资料回答，没有就说不知道」抑制瞎编。

## 核心价值

- **知识热更新**：加新文档即生效，不用重训模型，成本极低；
- **答案可溯源**：每条回答追溯到具体 chunk，可解释性强，答错知道哪条知识出问题。
