# RAG 面试题 23：RAG 与 Agent 自主文件检索应该如何选型？

## 核心答案

先分清两个被混淆的维度：**搜索方式**（关键词/正则/语义，怎么匹配内容）vs **取资料的流程**（什么时候搜、读到什么是否继续、下一步谁选）。RAG 不要求只能用向量，Agent 也可以调用语义索引——「RAG vs 文件搜索」实际是**预建索引流程 vs 运行时自主探索流程**的比较。选型看两点：任务是否需要根据中间结果继续探索 + 重复处理成本。**常见组合：索引先定位候选文件，Agent 再读原文、核对版本、补查关联材料**——两部分不必互斥。

## 预建索引：组织成本提前并复用

价值：解析和索引建立服务很多请求，不用每个问题重新探索相同集合；固定问答流程检索步骤易单独观察改进（找不到材料查查询与索引，候选多选错查排序范围），检索/生成阶段交接明确。局限：候选只是「值得阅读的材料」不是证明的答案——相似度高不等于适用，摘要可能省略条件，必要时仍要读完整章节核对来源版本；索引要维护（资料变索引没刷就返回旧内容）。适合：明确资料集合做成可重复使用的查询入口。

## 自主检索：资料获取进观察循环

关键：**下一次搜索由上一次观察决定**——读到新名称/引用/异常再据此继续查（说明引用配置、配置又指向实现，下一份材料的入口来自刚读到的内容而非用户最初问题）。代价：多轮工具+模型调用，不同任务轮数不同，延迟和读取量波动；不天然完整——猜错关键词、忽略目录、找到一份相关材料就提前停止，必要证据可能一直没读到。工具返回方式影响探索质量：**先给路径/命中位置/必要片段让 Agent 判断再读哪里**，比一次返回几千行杂乱内容更容易继续；长文件分段读取保留回查入口。搜索入口要适合线索：grep/rg 词面模式匹配适合明确错误码字段名；模糊描述需语义候选或先从目录说明获取真实术语。**模型生成同义词再交给 grep 是模型改变搜索策略，不是 grep 获得语义理解**——两层分清才知道找不到时该改什么。

## 选型矩阵

| 主要需求 | 更值得评估 |
|----------|-----------|
| 大量资料上的高频局部问答 | 预建索引 + 固定检索链路 |
| 依赖新观察、需追踪关联 | Agent 自主探索 |
| 大范围入口难找，找到后深入核查 | 索引定位后继续探索 |
| 少量资料需完整阅读整体理解 | 直接读全文 |

其他考量：资料组织（目录清楚主动搜索易获入口，规模大命名不直观索引缩范围）；更新方式（常变工作区建索引有同步成本，直接读文件读到的是当前可见内容但可能是旧副本/错误分支）；响应要求（固定链路易设步骤上限，自主探索限轮数/读取量/总预算）。**证据完整性是共同要求**——查到答案 ≠ 证明已检查所有文件，Top 几个候选或搜了几轮都不自动证明范围没遗漏。权限不随方案变化：能被搜索到不代表用户有权读取，由程序按当前身份控制。

## 组合方式

索引结果保留来源路径/位置/版本 → Agent 从候选回实际材料，查摘要有没有省略条件、原文件是否变化 → 证据足够就答，出现引用/相关配置/新未知点再补查。**第一批候选不能成为后续探索的围墙**——解释不了问题时允许改查询或查其他目录，不在候选文件里反复找并不存在的答案。控制成本：能直接回答的短问题不值得多轮探索；明确要通读的任务不必先做可能漏内容的检索。验证选型比较整项任务完成情况、证据充分性、总延迟费用——多读几轮可能值得，也可能只是搜索策略反复走偏，结合记录判断。
