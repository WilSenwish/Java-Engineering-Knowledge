## 模块一：Java 语言本质与跨平台机制

### 1. 核心原理

- **JDK / JRE / JVM**：JDK = JRE + 开发工具（javac/jstack/arthas 等）；JRE = JVM + 核心类库；JVM 是跨平台的执行载体。
- **跨平台原理**：`.java` → javac 编译为**平台无关的字节码 `.class`** → 各平台 JVM 将字节码翻译为本地机器指令。"一次编译，到处运行"的本质是**字节码规范 + 各平台 JVM 实现**。
- **执行方式**：JVM 混合模式 = **解释执行**（启动快）+ **JIT 即时编译**（热点代码编译为本地码，C1 快速编译 / C2 深度优化，分层编译）+ JDK9+ AOT（jaotc，JDK17 后实验性）。

### 2. 生产落地

- **JDK 版本选型**：生产主力选 **LTS 版本**（当前 17 LTS，跟进 21 LTS）；避免非 LTS 短期版本。项目约束：SpringBoot 2.1.3.RELEASE 兼容 JDK8/11，新模块可评估升级。
- **构建期固化 JDK**：Maven `maven.compiler.source/target` 与 CI 镜像 JDK 保持一致，避免"本地能跑、线上挂"。
- **字节码增强的生产用途**：SkyWalking 探针、Arthas 热更新、Mock 工具均基于字节码增强，无需改业务代码即可接入。

### 3. 踩坑规避

| 现象 | 根因 | 对策 |
|------|------|------|
| `UnsupportedClassVersionError` | 编译 JDK 版本 > 运行 JDK 版本（class 文件版本号不匹配） | 统一构建与运行 JDK；CI 构建镜像锁定版本 |
| 生产日志/接口中文乱码 | JDK8 `file.encoding` 依赖平台默认编码（Linux 常为 POSIX/ANSI_X3.4-1968） | JDK17 默认 UTF-8；JDK8 显式 `-Dfile.encoding=UTF-8`，容器内同步设置 `LANG=C.UTF-8` |
| 升级 JDK 后行为变化 | 小版本间 API/GC 默认值变化（如 JDK9 默认 GC 改 G1） | 升级前跑全量回归 + 压测；阅读 Release Notes 中 Removed/Deprecated 项 |

### 4. 优化进阶

- **JIT 关键优化**：方法内联、逃逸分析（栈上分配）、锁消除；写热点代码时避免方法过大阻碍内联。
- **GraalVM Native Image**：启动 ms 级、内存省，适合 CLI/短任务；但**峰值吞吐通常低于 JIT**、反射/动态代理需显式配置，中大型 Spring 应用需充分评估。

### 5. 选型对比

| 维度 | JDK 8 | JDK 11 | JDK 17 | JDK 21 |
|------|-------|--------|--------|--------|
| 支持状态 | 商业扩展至 2030 | 商业版 | LTS 主力 | 最新 LTS |
| 新特性 | Lambda/Stream | var、HttpClient、ZGC | record、sealed、switch 表达式、文本块 | 虚拟线程、顺序集合 |
| 生产建议 | 存量维护 | 过渡 | **新建首选** | 试点跟进 |

## 模块二：数据类型与包装类

### 1. 核心原理

- **8 种基本类型**：byte/short/int/long/float/double/char/boolean；默认值仅字段有（局部变量无）。
- **包装类与缓存**：`Integer` 默认缓存 **[-128, 127]**（`IntegerCache`，上限可 `-XX:AutoBoxCacheMax=` 调）；`Long` 同；`Short/Byte/Character` 全范围缓存；`Boolean` 缓存 TRUE/FALSE。
- **自动装箱/拆箱**：编译期插入 `valueOf()`/`xxxValue()`，是 NPE 与性能问题的常见源头。
- **浮点精度**：float/double 是二进制近似，`0.1 + 0.2 != 0.3`；金额必须用 `BigDecimal`。

### 2. 生产落地

- **数据库字段映射**：`tinyint→Byte/Integer`、`bigint→Long`、`decimal→BigDecimal`、时间用 `LocalDateTime`（JSR-310）而非 `Date`。
- **POJO 规范**（阿里规约）：DO/VO/DTO 等**数据对象一律使用包装类型**（便于 null 区分"未赋值"）；局部计算变量用基本类型。
- **BigDecimal 正确用法**：

```java
// 正确：String 构造器 + 明确舍入模式
BigDecimal price = new BigDecimal("0.1");
BigDecimal total = price.multiply(new BigDecimal("3"))
                       .setScale(2, RoundingMode.HALF_UP);
// 错误：double 构造器会把 0.1 的二进制误差带进来
// new BigDecimal(0.1) == 0.1000000000000000055511151231257827...
```

- **ID 设计**：内部 ID 用 `long`；对外暴露/跨系统 ID 用 `String`（防精度丢失，如 JS 大整数问题）。

### 3. 踩坑规避

1. **`Integer ==` 陷阱**：缓存范围内相等，范围外比较引用。`Integer a = 200, b = 200; a == b` 为 false。**一律用 `equals`**。
2. **包装类 NPE**：`Integer x = null; int y = x;` 触发拆箱 NPE。三目运算符两侧类型不一致也会触发隐式拆箱（`map.get(k) == null ? 0 : map.get(k)` 也可能拆箱）。
3. **整数溢出**：`long` 时间戳毫秒可支撑到公元 29227 年，但**雪花算法 41 位时间戳约 69 年耗尽**（需规划回用/重置策略）；`Integer.MAX_VALUE` 计数在千万级流量业务会溢出，用 `LongAdder`。
4. **float 比较**：循环累加 float 会漂移；相等比较用 `BigDecimal.compareTo` 或误差阈值。

### 4. 优化进阶

- **基本类型 vs 包装类**：数组/集合大数据量场景优先基本类型数组（`int[]` vs `Integer[]` 内存差 4~5 倍，缓存友好）；Java 无原语泛型，可用 fastutil/Eclipse Collections 或 flattened 结构。
- **`String.intern`**：JDK7+ 常量池移入堆，大量 intern 相同字符串可省内存，但字符串池是固定大小的 HashTable（JDK7 可 `-XX:StringTableSize` 调），滥用会拖慢。

### 5. 选型对比

| 场景 | 推荐 | 理由 |
|------|------|------|
| 计数/索引/时间戳 | `int` / `long` | 基本类型，无装箱开销 |
| 实体字段/接口出入参 | 包装类型 | 支持 null 语义，框架反射友好 |
| 金额/费率/比例 | `BigDecimal` | 精确十进制 |
| 跨端 ID | `String` | 避免 JS/JSON 精度丢失 |

## 模块三：面向对象与多态

### 1. 核心原理

- **三大特性**：封装（隐藏内部状态，暴露契约）、继承（复用 + is-a）、多态（运行期绑定，`override` 是实现多态的前提）。
- **抽象类 vs 接口**：JDK8 起接口可有 `default`/`static` 方法；抽象类可有构造器、字段、非 public 成员。**接口定义能力契约，抽象类封装共性实现**。
- **重载（Overload）vs 重写（Override）**：重载是编译期决定（同名不同参），重写是运行期动态绑定（子类实现父类方法）。

### 2. 生产落地

- **分层数据对象命名**：DO（数据库映射）/ DTO（跨层传输）/ VO（视图展示）/ BO（业务聚合），用 Lombok `@Data`/`@Builder`，禁止手写 get/set。
- **SPI 思想**：核心模块定义接口（如 `PayChannel`），实现方按约定注册，主流程面向接口编程（Spring 的 `FactoryBean`/JDK `ServiceLoader` 均基于此）。

```java
// 面向接口 + Lombok + ApiResponse 统一封装的 Controller 示例
@RestController
@RequestMapping("/api/v1/users")
@RequiredArgsConstructor
public class UserController {

    private final UserService userService;

    @GetMapping("/{id}")
    public ApiResponse<UserVO> get(@PathVariable Long id) {
        return ApiResponse.ok(userService.getById(id));
    }
}
```

### 3. 踩坑规避

1. **重写三约束破坏**：返回值协变（或相同）、访问修饰符不能收紧、受检异常范围不能扩大。违反编译期即报错，但**抛出的异常范围写更宽**这类隐性破坏需 review 卡住。
2. **静态方法"重写"无效**：静态方法是隐藏（hide），通过父类引用调用执行父类版本——多态场景误用静态方法是经典 bug。
3. **构造器中调用可重写方法**：子类重写的方法在子类构造器执行前被调用，字段尚未初始化，拿到默认值（JDK 建议：构造器中只调 final/private 方法）。
4. **`equals`/`hashCode` 契约**：`hashCode` 相等的对象 `equals` 不一定 true；`equals` true 则 `hashCode` 必须相等。用 IDE 生成或 Lombok `@EqualsAndHashCode`，重写 `equals` 必须同时重写 `hashCode`。

### 4. 优化进阶

- **final 优化**：final 类/方法使 JIT 去虚拟化（直接内联目标，省去查虚表）；热点小类可考虑 final。
- **组合优于继承**：继承破坏封装（父类实现变化影响子类）；策略模式用组合 + 接口替代继承体系。

### 5. 选型对比

| 方案 | 适用 | 不适用 |
|------|------|--------|
| 接口 | 定义契约、多实现、回调 | 共享代码（default 方法仅适合少量） |
| 抽象类 | 模板方法模式、共性状态 | 跨继承体系复用 |
| 继承 | 真正的 is-a 且层级稳定 | 需求多变的业务模型 |
| 组合 | 默认首选 | — |
